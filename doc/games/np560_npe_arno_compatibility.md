# 阿诺创世纪：实际场景、跨游戏存档隔离与冷读回

日期：2026-09-06。此次扩展第二个真实 NPE 样本，没有修改 CPU、ROM、原厂游戏或键盘映射。
结果属于已有通用实现的兼容性证据，不算新增硬件实现，也不表示整款游戏完成。

后续发现并修复：原记录中视口坐标可以移动，不代表背景滚动全部正确。
CPU 的 REP/REPB 共用状态使原厂背景搬移丢行；[后续修复](../cpu/np560_nested_repeat_scroll.md)
已用同一原生存档确认横向、纵向实际背景正确。
随后已取得[树林双敌战斗、逃跑及第二槽增量读回](np560_npe_arno_battle.md)的局部证据；
完整战斗、剧情和实际施法仍未完成。

## 实际完成的使用链

- 原厂文件 API 导入的《阿诺创世纪》由原厂游戏列表打开，从“新的征程”进入地图 1。
- 角色、视口滚动、碰撞和 F4 菜单可运行；“仙术”子菜单能显示角色阿诺，但本次未实际施法。
- 触发 mode 5 剧情文字“妈妈：啊..阿诺 你给我快起来..”，空格推进后回到 mode 1。
- 经地图 1 的 `(9,18)` 出口进入地图 3，装载完成后世界坐标为 `(1,25)`，朝下。
- 原厂“系统 → 存储进度”第一槽保存；随后切换《英雄传奇》，其第二、第三槽仍存在，
  第三槽恢复地图 4 / 世界 `(8,4)` / 朝左；再切回阿诺第一槽，恢复地图 3 / `(1,25)` / 朝下。
- 导出 NAND、结束 writer，再以同一 QEMU/PRG/ROM 的全新 reader 冷启动，
  直接选择阿诺“再续前缘”第一槽，未先开始新游戏，恢复同一地图、位置和方向。

**尚未完成：** 阿诺的完整剧情、技能、装备、战斗、全部存档字段及错误路径、有声运行。
原厂音效配置始终为“关”；第二样本没有绕过或补齐已知音频 ROM 缺口。

## 地图证据与操作纠正

数据 `52:70B4` 为当前 15×7 格视口 tile word 数组，原厂 runtime `28:0C76`
依据这些 tile 值判断通行。原始 PRG source 对应 `45:0C76..0F90`。
此例不是收到方向事件却漏执行：桌椅、床、隔墙相应格会被原厂碰撞规则拒绝。

在视口偏移 `(5,13)` 时，七行 tile 数值可在原始阿诺 NPE 中逐项找到，
第一行从文件 `0x10C0D9` 开始，每行相距 40 字节，数值为 big-endian u16。
依照实际地图宽 20，得到该张 20×20 地图数组起点 `0x10BEC7`；
105/105 个视口格与对应原始文件格相同。仅用于理解原地图和选择物理按键路线，
没有把宿主推导的路线、碰撞结果或坐标写入游戏状态。

右侧房间通往中央走廊的路径经过最右列 X=19，不能把 X=18 上方的床/柜子受阻当作地图坏了。
原厂出口表 `52:6B82` 起、步长 24，第二项坐标 `(9,18)`、目标地图 3；
实际出口装载和 LCD 场景改变与该记录一致。

本样本九项头部值及首 section 布局不同于英雄，但仍使用 `NP560 RPG2.1`；
不能据此宣称是另一种引擎。两者 section 16 开场音频相同，也没有新增解码算法证据。

## 存档与进程边界

writer 新建阿诺存档前的原厂槽位为 `一 0 / 二 0 / 三 0`。
确认第一槽后 NAND PROGRAMS `192→642`、ERASES `11166→11173`、COPIES `141→581`，ERROR=0。
后续退出等原厂操作使导出前 PROGRAMS 为 658。

| 观察点 | 原厂槽位/恢复结果 |
| --- | --- |
| 阿诺第一次存储前 | 三槽全空 |
| 保存阿诺后打开英雄“再续前缘” | `一 0 / 二 1 / 三 2`；第三槽恢复原树林位置 |
| 再打开阿诺“再续前缘” | `一 1 / 二 0 / 三 0`；第一槽恢复室外位置 |
| 全新 reader 打开阿诺“再续前缘” | `一 1 / 二 0 / 三 0`；第一槽恢复地图 3、screen `(1,4)`、offset `(0,21)`、direction 0 |

reader 冷读阿诺存档时 PROGRAMS 始终为 48（启动阶段已有值），读取没有新增编程。
冷读后原厂属性页显示阿诺、金钱 100、等级 1、经验 0/10、生命 119/130、真气 59/60。
这些是 reader 的实际显示；本次 writer 未逐项抓取属性页，不能声称全部属性字段均已作保存前后比较。

NAND 导出通过现有 QOM `nand-save` 实现。writer 未配置 Web 自动保存，
因此暂停自己的 QEMU 后，以宿主 GDB 调用现有 `object_property_set_str` 导出；
不是通过改 RAM 生成存档，不是整机快照，也不是已交付的 Web 内容管理入口。
第一次 GDB 表达式因多余反斜杠被拒绝，未执行；修正引号后的调用返回 1。

原输入未覆盖，新导出仅增加一个必要的 553,648,192 字节 E 盘文件。
writer Web/QEMU PID `77942/77944` 与 reader `79217/79219` 均已正常退出 0。
本轮端口 `33641/41789` 已关闭；没有操作用户的 8807/8808/8809。

## 自动关屏旁证

长时间放置的 writer 在本轮开始前进入 `DISPLAY=off / SLEEP=on`；Enter 没有唤醒。
当前原厂 X RAM 电源等待代码读取 `F160 & 0080`，现场 drive 为 `F164=3F00`。
物理 M61 使相应列拉低，实际恢复每日一句并可返回系统，不需要重启或修改内存。
见 `play/08-after-enter`、`09-physical-wake`、`10-wake-dismiss`。

这只证明该场景的原厂关屏/恢复路径有响应，**不证明真机电源键接线、CPU 低功耗、
全部唤醒来源或游戏现场恢复已完整实现**；恢复后需要重新进入游戏。
旧 `v814_live_trampoline_001002` 反汇编不能直接代表当前 X RAM 中动态复制的电源代码。
