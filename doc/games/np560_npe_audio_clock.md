# NPE 声音驱动服务计时

2026-10-10更新：[初始双半缓冲预填](np560_npe_audio_initial_pcm.md)已接入；首帧计数更新顺序按原初始化修正。

2026-10-08。将原 PRG 的播放服务计数移植到纯 C，并接入 SDL 半帧准备与清理阶段。生产程序仍只依赖 C11 与 SDL2。

## 原程序依据

原文件 `tmp/NP560.PRG` 的 SHA256 为 `d555609e03ece17f42c1881beeb88361572f18621161de67bc9dc765857089f5`。`tmp/npe-audio-lifecycle-original-source.asm` 使用源地址 25 段；对应以下运行地址为 08 段。

| 运行地址 | 操作 | 对应 C 服务 |
|---|---|---|
| 08:385C | 由采样率与输出 word 数配置单次增量 | `npe_audio_clock_configure` |
| 08:37F4 | 48 位计数加 32 位增量 | `npe_audio_clock_advance` |
| 08:3820 | 减增量，最终高 word 为负时清零 | `npe_audio_clock_retract` |
| 08:37CE | 加整数毫秒，保留低 16 位小数 | `npe_audio_clock_add_ms` |
| 08:37BA | 返回计数的整数毫秒 | `npe_audio_clock_ms` |

计数保存在原内部 RAM 4A52/4A54/4A56，增量保存在 4A58/4A5A。计数为 48 位 Q16 毫秒，运算按 48 位回绕。减法判断最终符号位，不能替换成无符号大小比较。例如 `0x800000000000 - 1` 得到正的 `0x7FFFFFFFFFFF`，原服务保留该结果。

配置函数先计算 `words * 1000`，两次 UDIVL 分别获得整数与小数字。原代码按余数大于 `rate >> 1` 才进位。正常参数 32000/320 得到 10 毫秒增量。C 实现保留 word 运算顺序。

**商溢出限制：** 当前 DMCU 模型在商超过 65535 时保留 R6/R7，C 保持该模型的结果。22 组参考中的 1/65535 覆盖这条路径，得到 `0xFC180001`，与宽整数除法结果不同；该结果尚无原芯片实测证明，不能把模型对照当作芯片溢出语义已确定。资料歧义记录见 [除法资料核对](../cpu/np560_crit_interrupt_boundary.md)。正常 32000 Hz 播放参数不触发该分支。宿主 API 对零采样率返回 −1；这不是原芯片除零行为的证明。

## SDL 接线

原 2F:6756/67C8 在完成一次半帧服务后调用 08:37F4；计数发生在之后的物理传输之前。现在 SDL 每准备一个 80 源样本半帧就推进一次，输出 word 数改变时重新配置增量。保留准备好的半帧，后续回调只消耗它，不重复计数。

- 启播前已经准备两个初始半帧，计数为20毫秒；初始快照为零。
- 消耗首帧1280字节期间保持20毫秒；请求第1281字节准备下一半帧，计数为30毫秒。后续帧逐半准备。
- START_WAIT 的静音字节不推进计数。
- 原 08:3292 在清理等待后清五个 word；SDL 的 CLEANUP_WAIT 完成时同时清计数和增量。
- 有限播放EOF的停止等待保留计数；下一次请求完成清理后清零，再在启动等待前预填两个半帧至20毫秒。
- 资源解码失败不推进计数，随后清理将其清零。

这项计数是驱动服务状态。它与 SDL 消耗字节数、DAC 已播放位置、Timer2 等待计数及宿主时间各有独立含义，不能用来宣称物理播放时序已复刻。

## 对照证据

`npe-sdl/tests/reference_audio_clock.py` 隔离执行原 PRG 的五个服务，核对原函数 CODE 字节，保存每次操作后的全部五个 word。未执行 codec、文件服务或音频 IRQ，也未向运行中的来宾 RAM 写状态。22 组原指令路径有 116 个检查点，含小数进位、整数进位、48 位回绕、符号减法、整数毫秒回绕和配置边界。每组恢复栈并保留计数两端的 guard。

`generate_audio_clock_fixture.py` 从 `tmp/audio-clock-native/report.json` 导出冻结数据；`sdl_sound_probe.c` 对每个中间检查点以及最终 getter 比对。SDL 追加检查回调拆分一致、清理清零、有限 EOF 保留、22 个资源的循环尾部和解码失败。尾部隔离检查显式注入诊断计数，不能作为整轨原播放时长的证明。

本轮四目标构建无警告，声音检查、答题声音请求检查、场景动画检查均退出 0。答题保留 6 条原路径及 6 条初始停止案例；场景保留 281 次 C/SDL 原画面对照。冻结记录为 `tmp/audio-clock-report.json`，原参考位于 `tmp/audio-clock-native/`。

## 仍未完成

压缩 PCM 仍为候选解码实现，既有 6 个 PCM 帧的哈希只能证明候选算法一致，不能证明原声一致。已有前端 WAV 来源于独立 MRC，不能作为相同 NPE 压缩轨的 PCM 参照。需要原始 mask-ROM、原厂解码库或同一 NPE 的原机 PCM 采样才能继续确定 codec；本轮没有填充这些缺失入口。

原芯片商溢出、完整音频 IRQ 计数、DAC 物理时序、冷 GPIO、阻塞请求时间及压缩流的实际结束位置继续待还原。原机存档互通和两项全程游玩验收按用户要求取消；自身存读档和必要短验证保留，整体粗估仍约 80%。
