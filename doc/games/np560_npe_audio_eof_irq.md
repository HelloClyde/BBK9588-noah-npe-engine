# 原声音结束中断与回调

2026-10-07。此次执行原结束中断、回调保存／派发／恢复及原清理／启动服务。生产程序仍为纯 C11＋SDL2。

## 范围与原指令

`npe-sdl/tests/reference_audio_eof_irq.py` 使用原 `tmp/NP560.PRG`，SHA256 `d555609e03ece17f42c1881beeb88361572f18621161de67bc9dc765857089f5`。Windows QEMU SHA256 `db37a4e04e9fd1d9190b36aaea0a33c68ce75773c966ee1199d6a62836b12cb6`。

外围客机设置实际 DPRAM 状态、DAC、RAM、回调指针及诊断寄存器，执行 TRAP34。只将软件 TRAP 的固定 `01:00D0` 向量改为跳到原 `08:3B48`；被测中断与被调用原服务字节保持。Timer2仍使用原等待器与实际中断倒计时。没有NAND、宿主写客机RAM或解码器替身。

**结束位由诊断直接设置**，没有执行压缩输入补充来产生它。诊断回调在 `20:1000`，记录实际入口状态后直接返回，或调用原 `08:3262→4702`。它没有执行地图／战斗原回调中的资源重新打开，不能把这项证据称为完整音轨EOF和重开证明。

## 结果

| 路径 | Timer2计数 | 回调 |
| --- | ---: | --- |
| 有限播放，未注册回调 | 50 | 无 |
| 注册回调，回调直接返回 | 50 | 一次 |
| 注册回调，原清理→启动服务 | 300 | 一次 |
| BIT89.0、.1、.2分别置位 | 各0 | 无 |
| BIT8D.0、.2分别置位 | 各0 | 无 |

八条路径全部返回原前台PC，栈回到6000；R1、R2、R3、R7的不同诊断值保持。回调路径实际执行原 `39F4→3A00..3AB0→3AB2..3B46` 的保存、合成中断返回帧、派发和恢复，没有跳过这段机制。

原结束服务首先清89.12／.13／.14，五种占用状态随后阻止停止和回调。回调入口读到88仍为1，89为8808：结束位及注册位保留，回调活动位.3已置位。直接返回后.3清除，89为8800。经过清理服务后89为0。这些都是实际DPRAM读数。

## 修正旧诊断的状态设置

BIT88／89／8D分别对应DPRAM `F010／F012／F01A`。直接写SFR88等编号不会设置这些位。新诊断初版暴露了此设置错误；修正实际地址后重新运行，以上八条路径通过。

`reference_audio_wait_chain.py` 的旧 `MOV REG88` 设置同时更正为客机写F010，加入“原驱动已空闲时停止”路径。六条重新执行通过：200、250、300、50、0、1200计数。此前五条的计数没有变化；旧报告对初始空闲状态的设置不能作为依据，以这次实际DPRAM设置的报告为准。报告和CPU轨迹已由修正版重新生成。
