# 原声音输入缓冲与纯C接入

2026-10-07。纯C候选解码器已通过1024字节窗口及两个4096字节输入缓冲读取当前NPE，不再在每一帧直接按全文件偏移提取字段。

## 原指令动态证据

`tests/reference_audio_input_refill.py` 执行完整、未修改的原 `2A:87EA..8A52`，包括 `2C:0D72/0DCA` 的搬移／复制和 `31:0276` 的输入缓冲切换。随后执行原 `2F:66F2`，关闭两个PCM输出半区，仅检查真实结束条件。外围诊断设置两个源缓冲、窗口、DPRAM及元数据，源词值分别从2000／3000开始，窗口词值从1000开始，便于区分搬移和两个源的写入顺序。

原PRG SHA256：`d555609e03ece17f42c1881beeb88361572f18621161de67bc9dc765857089f5`。Windows QEMU SHA256：`db37a4e04e9fd1d9190b36aaea0a33c68ce75773c966ee1199d6a62836b12cb6`。没有NAND、宿主改写客机RAM、codec替身或原文件读取服务。16条路径均保持返回栈，未出现缺失ROM或不支持指令。

覆盖零消耗、只取当前源、跨源部分读取、反向缓冲切换、刚好耗尽、输入不足、上次不足量续接、空下一个缓冲、生产者标志、两生产者忙及其传输状态分支、32位尾指针减法、零输出、已有结束位，以及尾指针前／相等／后。保存完整512词窗口、源指针、剩余数量、两个待用数量、不足量、尾指针和DPRAM状态。

**范围：** 解码器游标和输出长度由客机诊断提供；没有执行B816/B84E/B7AA、输入文件生产者、结束IRQ或游戏资源重开。原结束判断是输出长度零或无符号32位游标大于尾指针；等于尾指针不会置结束位。已有结束位不会被清除。

诊断的RAM快照使用实际数据银行布局：一个DS选择器覆盖8000字节，窗口物理8800，A2银行元数据物理5129D0。初版观察地址按10000计算，读到了错误银行；更正地址并增加非零源指针／窗口内容断言后重跑，当前报告来自修正版。

## 纯C服务

`audio.c` 的 `npe_audio_input_refill()` 按原服务顺序执行：

1. 搬移当前窗口未读词；
2. 将之前不足量与本次消耗相加，回退追加位置并清旧不足量；
3. 取当前源，必要时按原标志切到另一源，清其待用数量；
4. 两生产者忙时保持原源指针，标记忙状态，并按传输状态清请求位；
5. 第二源不足时，在复制它之前设置32位尾指针，保留 `frame_bits>>4` 词的扣除；复制可用词，记录不足量；没有后续文件字节时清补充标志。

`npe_audio_input_check_end()` 保留原无符号比较及结束位的保持行为。它已和16份原轨迹对照；没有将未知B816游标替换为候选游标来控制SDL结束。

`generate_audio_input_fixture.py` 直接导出原512词内容和元数据。实际C声音探针逐项比较所有字段、完整窗口及结束结果；夹具没有依据C实现生成。

## 候选解码器接入

`NpeAudioInput` 保存窗口、两个源缓冲、状态及字读取器。`npe_audio_input_open()` 从当前NPE真实字节创建候选输入，按完整偶数输入交换字节，不改文件、不裁尾字、不替换音轨。每次播放／循环重开重新初始化输入状态。

候选字段读器逐词读取、每字节MSB优先；奇数长度的21字节帧保留已读词中的剩余8位到下一帧。窗口补充使用上述原C服务，当前源耗尽后请求旧源再填充。NPE已在内存，宿主生产者按原静态代码中的4096字节上限同步填充。回调没有分配内存、磁盘读取或外部执行依赖。

原 `2B:2894` 的静态摘录保存于 `tmp/audio-input-producer-original.asm`，其文件读取上限为1000十六进制字节，读取长度除二后记待用词数，交换每个完整词并减少文件剩余数量。但此次**未动态执行原文件生产者**。候选初始化先消费4字节格式头、每帧168位，以及宿主同步生产者的调用时机，均是候选适配；原B6DE/B816的头处理、预取、游标与中断时机仍未证明。

增加的压缩缓冲为1024＋2×4096＝9216字节；PCM仍只缓存160词／320字节。资源及完整NPE继续驻留内存。解码候选状态和输入状态一起事务提交，解码失败不会把部分新帧状态写回正在播放的解码器。
