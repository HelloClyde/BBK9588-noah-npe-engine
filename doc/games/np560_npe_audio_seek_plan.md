## 原动态范围

`npe-sdl/tests/reference_audio_seek_plan.py` 从客机 prologue 进入原范围后续，保留原转换、比较、XOR `31:EB24`、交换 `2C:0E1E` 和时钟设置 `08:37CE`。B6DE／B84E 用客机记录参数的边界替代，文件 seek `1B:C5EC` 和 read `1C:CCD4` 用客机捕获／RAM 读取替代；到 `25:E24C` 前退出，零读仍走原 FFFE 返回。没有运行原范围三次探测、codec 内部、初始 PCM 或实际 EOF。

24 条路径：四条当前 NPE 真实段长度／位置参数（16、17、31、36），以及二十条诊断边界，覆盖头前／头相等／头后、非整字节位偏移、起点等于／大于剩余长度、范围末尾小于／等于／大于剩余长度、零范围／零读／短读／奇数 XOR、1024／1026 请求、大位数高位丢弃、绝对偏移回绕、零剩余及宽头位数。四条 NPE 样本的范围位数来自明确的候选 168 位布局，窗口仍是诊断内容，未声称原实际 codec 位置。

## 原规则

1. 保存起点的低四位为解码恢复位偏移。起点和长度均按 `(bits >> 3) & 0x00FFFFFE` 转成偶数、24 位字节范围；不自动向上取整。
2. 起点不超过 `header_bits >> 3`，或**大于**原剩余长度时，调用 B6DE 重置到 8800／偏移 0，把剩余量直接替换为转换后的长度，不重新读窗口。
3. 其余情况寻址。起点**恰好等于**剩余长度仍进入此分支；截取后剩余量为零，但照常 seek 并发起零长度读，原返回 FFFE。不能把等于误写成重置条件。
4. 寻址分支：原剩余量不大于 `start_bytes + length_bytes` 时，用 `old_remaining - start_bytes`；否则用长度。文件绝对偏移为 `resource_offset + start_bytes`，保留 32 位回绕。
5. 请求 `min(remaining,1024)` 字节。零读立即错误返回；正数读做 XOR 和完整词交换，奇数尾字节只 XOR 不交换。**短读不把 remaining 改成实际返回，也不扣除实际读数**；后续初始窗口服务另作窗口扣除。
6. 正数读后调用 B84E 恢复到 8800／保存的低四位，再设置量化后的时钟。后两项调用参数在原参考中捕获或保留，实际 codec 恢复和物理时基未证明。

## C 服务与接入限制

`audio.c:npe_audio_seek_plan()` 保留原转换、相等边界、截取、请求及偏移计算，输出 `NpeAudioSeekPlan`；`npe_audio_seek_window()` 在调用方完成 seek 后执行原窗口读取／XOR／交换。返回 0 表示需要重置且不用读，1 表示正数读后需要恢复，-2 表示原零读失败，-1 仅用于无效主机参数。函数不冒充 B6DE／B84E 已实现。

窗口读取与现有生产者共用 `input_normalize()`，保留已经验证的奇数字节处理。当前默认候选输入把新计划存入 `NpeAudioInput.seek`，并检查默认四字节起点走重置分支。资源中真实载荷与候选布局供给这些元数据；实际候选播放器继续采用已声明的载荷长度和帧数规则。因为原 B6DE 头部消费／预取尚未确定，不能把偶数向下截取后的范围直接套到候选字段读取上，造成末帧丢失。
