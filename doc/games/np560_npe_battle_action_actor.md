# 战斗菜单角色与实际行动者分离

更新于2026-10-09。接续[战斗执行控制](np560_npe_battle_execution_control.md)。生产仍为C11 + SDL2，画面、角色、仙术和道具资源来自当前NPE。

## 原版差异与修正

原52:7A9E是菜单选择的角色字节，52:7ACC是物理执行索引。原39:58C8..6072调度器通过7ACC选择记录，不逐人改写7A9E。此前C循环在每个己方行动前把`battle_actor`改为行动者，使该共享地址在动画中错误地变化。

本批增加`npe_world_battle_action_actor`：执行过程中读取7ACC所指的物理记录，菜单调用继续读取7A9E。移除执行循环对菜单角色的逐人写入，攻击／防御／联合、仙术、使用／投掷道具及相应动作绘图改读物理行动者。数值字段、技能／道具缓存、扣费和动作资源都由同一物理角色消费。

正常指令收集结束按2F:CA70从角色0重新扫描可选人，再派发物理行动；围攻准备后的外层入口按2F:C63C写菜单角色0，联合按2F:C6D4写0。回合末继续按38:FEFC／FF14重新扫描下一次菜单角色。没有增加World状态副本，绑定仍为3545字节；自身NPESAV22载荷和已有暖恢复规则保持。

这些修改保留原菜单选人与实际行动的不同含义。调试绘图在没有执行回合时仍可用菜单角色选择动作，实际执行通过物理索引选人。

## 原版证据

原`reference_combine_animation.mjs`增加独立`--menu-actor`采样目录。原文件和已有参考保持。每次推进结束后保存菜单角色、执行索引与行动标志，原提交画面逐字节复查。

| 原公共路径 | 路径数 | 参考画面提交 |
| --- | ---: | ---: |
| 围攻，包括速度换序、睡眠／倒下和替换已选防御 | 6 | 153 |
| 双人／三人普通攻击序列 | 2 | 57 |
| 联合单轮 | 6 | 168 |
| 联合连续两轮 | 2 | 112 |
| 合计 | 16 | 490 |

这16条路径的490份原采样菜单角色均为0；物理执行索引仍随实际行动变化。菜单字段在这些行动期间保持，原角色间恢复、伤害和返回菜单的画面保持。原采样RAM仍来自推进结束时，不能泛化为所有原LCD瞬间的RAM采样。

原调度器及菜单重置／扫描片段保存在`tmp/battle-menu-actor-controller-source.asm`；独立汇总检查原PRG六处菜单角色写入指令，并确认保存的调度器片段没有引用7A9E。

## C与SDL验证范围

三个新探针沿用原动画／数值对照，并在实际SDL提交处检查World与原地址7A9E：围攻、普通攻击序列、联合／连续联合共490份实时菜单角色快照。围攻及普通攻击的直接C绘图回调另外保存210份快照。联合直接C的画面对照是分段重建，未将它算为实时控制字节的回调证明。

构建及必要回归结果以`tmp/battle-menu-actor-report.json`为准，由`npe-sdl/tests/verify_battle_menu_actor.py`重读原采样、保存的C结果、退出日志及前批证据汇总。完整检查清单保存在`tmp/battle-menu-actor-check-targets.json`。

83个目标构建无警告，82项必要短检查最终全部退出0，独立汇总通过。前批1305份证据及原文件／字库哈希保持。

### 失败逃跑入口

沿用原双人队伍、第二名角色选择随机逃跑失败的公共参考：41份原提交元数据的菜单角色均为0。新增实际SDL提交断言首先复现了C保持角色1的错误，修正失败逃跑后的角色重置／扫描后，33份行动期间实时菜单角色快照通过。原确认菜单和首个保留提交的两次整屏对照仍通过，预扣道具保持消耗、攻击行动及返回旗帜按钮的断言保持。

该探针的返回按钮计数原来在逃跑函数返回后才启用，但菜单已在内部按原顺序提交；修正计数启用位置，保留原按钮值断言。两次失败日志保留。它不证明后续41幅失败逃跑画面全部一致，尚未覆盖其它失败逃跑调用者。

失败逃跑补充修正只改这个入口的菜单角色重置；正常路径的81项结果保留，仅重建生产程序和对应探针、重跑该项短路径。`tmp/battle-menu-actor-world-before-flee.c`保留第一阶段源码，独立汇总要求当前world.c与它的差异恰好为这三行入口逻辑，避免将其它未验证代码修改混入原结果。
