# NP560 NPE：学技扫描的活动字节与离场写回

## 修正范围

原学技服务读取战斗驻留记录。18个技能槽之后的第一字节是`647B`活动标志，运行中可以变化。C此前从人物NPE资源的`raw[76]`重新取得初值，导致相同技能槽、等级和缓存下装载不同技能。

现在用独立的`battle_party_record_active[3]`保存这三个驻留字节：入战时复制地图活动字节，学技读取当前战斗副本，离场时按原队伍前缀写回地图。用于宿主战斗循环的成员前缀仍由末端零标志裁剪，不能代替记录中的原字节。

原参考使用真实投掷159及防御排队、原胜利和升级服务。仅在诊断RAM中把首成员战斗活动字节分别改为0、2、4、6；原PRG、NPE、文件与LCD服务保持不变。测试参数与中文诊断缓存只存在于夹具。

## 源码依据

`43:C1A0..C234`以字节索引访问`6469 + 148×成员 + 索引`，先调用共享技能装载，再检查18槽界限。索引18即`647B`。`43:C36A`重新装载当前显示编号，`43:C41A`装载下一个编号。

入战服务`49:8D64..8DE0`只从末端裁剪零标志，中间空位仍属于队伍前缀。离场的`2F:C1E2`／`33:C73A`把战斗记录写回地图，不应重新恢复入战前的旧活动字节。

本轮留存的反汇编为`tmp/learn-resident-source.asm`。原完整后续显示循环还会读取`647C`群攻、更多字段和邻接记录，并采用字节索引回绕；当前C仍有限制。这些行为继续列为待办，不能用本轮四例证明完整148字节布局已完成。
