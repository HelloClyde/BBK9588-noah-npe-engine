# 普通攻击与防御交错：姿态、行动次序与相邻敌人恢复

更新于 2026-10-06。九条独立原厂输入序列、24 次实际攻击／防御行动、327 个全体记录阶段、九张最终 SDL 整屏和 151 次动作提交通过 C／实际 SDL 对照，均零差异。这里验收的是下表场景，完整战斗动画和整款游戏仍未完成。

## 原厂证据与实现

- 原厂防御类型为 5。`2F:CDB4` 的分派表将类型 5 跳到 `2F:DEFA` 返回，保持动画组为零；`39:5DEE..5FFE` 跳过普通攻击的接近／挥击，执行防御姿态绘制。
- `32:EF78..EF80` 和 `31:8200..8208` 按各个记录自身的类型 5 选择姿态 4；图像编号来自当前 NPE 角色记录，不写死角色或游戏。绘制覆盖零像素，清除矩形保留原厂包含右／下边界的方式。
- 九组动态采样确认防御姿态重画当前行动者和第一名在队记录。三人全防御时，第三人行动只重画第一人和第三人；第二人的画面已恢复普通姿态。第一人尚未行动时，也按已经排队的命令选择其姿态。显示目标服务的完整赋值链仍待追踪，不能据此宣布全部防御绘制分支完成。
- 防御已有的数值服务沿用 `2D:4F44..507A`：当前防御写入基础防御加 100、低字及有符号封顶规则，替换此前仙术防御效果；计时写 2，回合末降到 1。本轮接入显示观察回调，不改数值算法。
- `30:13E0` 对类型 5 跳过伤害飘字；每名防御者贡献一次姿态提交、一次动作后刷新。普通攻击贡献九次提交；末尾另有两次角色刷新及四次命令页提交。因此整轮提交数为 `6 + 2×防御人数 + 9×攻击人数`。
- 行动之间沿 `33:C868..C876` 刷新现有缓存，保留原厂场景擦除和已扣体状态。记录全部命令后按速度执行，菜单保留上次旗帜子项的位置。

## 第三敌槽攻击暴露的归位缺陷

第一次额外采样错误地用右键选敌，原厂选敌只响应上／下键，因此实际仍攻击第一槽。已修正采样及 SDL 输入为下键，并以显示目标字段确认第三槽；错误采样不计验收。

正确采样随后发现第 5 次提交差 635 像素，位于 `(42..74,64..87)`：C 清除攻击者在第三敌槽旁的临时矩形时，擦掉了相邻第二敌人的下半身。`31:849C..869A` 明确检查攻击目标在第二或更后敌槽、行动者属于队伍，并在归位后重新绘制前一物理敌槽；该槽有符号体力必须大于零，采用覆盖绘制，不另清空背景。已按此规则修正 `npe_render_battle_attack_stage`，九组重新全帧通过。没有加入敌人 ID 特例。
