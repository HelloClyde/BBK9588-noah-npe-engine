# NPE 战斗属性倍率与带符号除法

更新：2026-10-06。规则来自原 PRG、独立原厂输入及原指令片段的 CPU 执行；读取当前 NPE 字段，不按游戏或角色 ID 特判。

## 装载与计算

敌人记录的 `+27` 大端字经源 `31:CE26..CE72` 装载到战斗记录 `64AA`。C 的随机遇敌、地图追击和剧情战三个入口均保存该字，己方读取现有 `other_stats[][2]`。

角色源 `2D:37A4..37C2` 和敌方源 `33:6F16..6F34` 使用同一计算顺序：

1. 将双方属性相加，保留低 16 位，并解释为带符号除数。
2. 行动者带符号属性除以上述值，商向零截断。
3. 商乘本次 `随机值 % 100`，保留低 16 位并解释为带符号数。
4. 带符号除以 80，向零截断，再加 1。

CPU 的除零或商超出带符号 16 位范围只设置溢出标志，保留原寄存器。C 计算按本仓库 DMCU CPU 实现的此语义处理。属性乘积低字参与普通伤害，之后仍分别走己方限幅及敌方双浮动规则，见[普通攻击规则](np560_npe_battle_signed_values.md)。

第二个随机值此前已抽取但被丢弃；现保留并用于倍率。没有增加随机抽取次数。属性和倍率是战斗暂态，地图存档仍为 NPESAV15。

## 原厂输入结果

`reference_attribute_multiplier.mjs` 在独立 RAM 夹具中以一名队员、三个原物理敌槽、中间一敌执行实际确认按键。己方样本的敌人处于乱状态以隔离己方伤害；敌方样本正常行动。每次恢复要求唯一 RAM 候选，采完后只清除退役夹具的模式签名。

| 行动者属性／目标属性 | 己方扣敌体 | 敌方扣己方体 |
| --- | ---: | ---: |
| 1／1 | 3 | 8 |
| 100／-99 | 3 | 8 |
| 100／-101 | 3 | 52 |
| 1000／-999 | 10 | 266 |
| -32768／32767，商溢出 | 3 | 8 |
| 32767／32767，属性和回绕 | 3 | 8 |
| 100／-99，行动者攻 1000，伤害乘积回绕 | 993 | 8 |

原厂控制样本确定己方浮动 -3、属性随机 1，敌方浮动 -2、属性随机 44。C 的控制种子 70768 复现这些抽取结果，不表示还原原厂启动 RNG。

共 **14 条完成的原厂输入、112 个记录阶段**。`sdl-attribute-multiplier-probe` 先对照 C 行动，再通过实际 SDL 主循环两次确认按键，核对入场／回合后的体、气、属性、当前攻防、两个计时字和四状态。参考没有新增整屏画面，累计整屏仍为 **317 张**。

另有 **6 条输入**的属性和为零，原厂前端返回 `execution_fault`，没有回合完成结果。这些输入保存在采样报告中，排除于 14 条成功参考；不能据此宣称原厂游戏的异常恢复行为已验证。

## 独立 CPU 片段与验证边界

`reference_attribute_cpu_slice.py` 从原 PRG 原样提取 `2D:37B2..37C2` 八个指令字，设置输入寄存器后在仓库的 QEMU DMCU CPU 中执行。九组属性分别使用随机 1、44、99，导出 **27 组倍率**；包含属性和为零、商溢出、和与乘积回绕。C 的公共计算函数与这些 CPU 结果逐项一致。

该工具用于检查原指令的算术语义。QEMU 不参与 C／SDL 产品运行；CPU 片段没有原游戏菜单、调度、异常恢复或连续剧情，不能充当整场战斗验收。

生成器将成功战斗记录和独立 CPU 结果分别固化在 `attribute_multiplier_native.h`，两类证据分开计数。
