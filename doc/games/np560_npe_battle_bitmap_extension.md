# NP560 NPE：战斗位图的驻留／文件分支

## 原分支与实现

原战斗绘图 `31:8276..8286` 将当前姿态编号交给运行时 `28:8ED8`，对应PRG物理 `45:8ED8`。原 `45:8F0A..8F14` 判断一基图号是否大于29；这个边界固定在引擎代码中。

| 原分支 | 地址与读取 |
| --- | --- |
| 图号1～29 | `79A6`驻留图组；三字节小端偏移；现有第9段位图 |
| 图号大于29 | `79CA＋low16(6×(图号−29))`文件目录；分两次读3字节 |

文件分支的两个读取目标是相距两字节的局部变量 `FFEC` 和 `FFEE`。第一组第三字节被第二组覆盖；后续消费第一组前两字节形成有符号16位偏移，第二组前两字节形成16位读取长度。位图载荷地址为 `79CE＋sign16(偏移)`，保留32位地址回绕。原目录位移只使用乘法结果低16位。

独立原快照的 `79CA=858`、`79CE=15098`，分别是当前NPE第0／1段地址。此分支按原6字节步长消费文件字节，不能改成常规8字节索引，也不读取人物头像使用的 `vectors[6]`。上轮把512解释为“全局图组1667＋512超过1780条目录”不适用于这条战斗绘图调用，现已更正。

`npe_battle_bitmap`保留低图号驻留读取，接入这个独立文件分支。长度0没有可绘制内容，调用者继续提交LCD；短头只解码原读取供应的前缀，不借用文件后面的完整头。在已验证的长度2路径中，只有位图签名，几何为空，继续后续动画。长度196路径解出当前NPE的16×16地形图并按原位置绘制。

这仍不是完整原文件IO／堆内存服务。目录短读、载荷EOF、其它部分载荷、非法格式、堆分配失败与原RAM别名继续待办。
