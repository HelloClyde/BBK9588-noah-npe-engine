# 敌方普通攻击：原厂动画与数值对照

更新于 2026-10-06。纯 C／SDL 已接入敌方普通攻击的接近、受击、防御姿态、友方飘字、归位及回合刷新。六条原厂完整输入的 **15 次实际行动、128 个全体记录阶段、六张最终 SDL 整屏、123 次 C／实际 SDL 动作提交**全部零差异；本类按完整像素去重 77 张。加上既有普通攻击、围攻、联合攻击及防御交错，共 839 次提交、去重 304 张。静态 334 张单独统计，未计算与动画之间的交集。

## 六条独立原厂输入

`reference_combine_animation.mjs --enemy-attack` 采集前两组，`--enemy-attack-extra` 采集后四组。每组恢复同一原厂战斗快照，从真实剑／旗帜菜单输入后记录整轮显示提交。仅隔离 RAM 的队伍、角色／敌人属性与状态被修改；原 NPE、PRG 与连续主线诊断存档未改。这些是开发夹具，不是自然难度游玩轨迹。

敌方攻击字 120、等级 10、技能槽空，仅指定敌槽可行动。已排队防御的队员在实际防御加成尚未执行时也享受减伤；此规则及数值公式已有实现，本轮未改。

`generate_enemy_animation_native.py` 从完整事件导出记录、动作、最终选中队员和提交数。普通攻击只有一个存活敌人时，第一次确认直接执行；不会增加原厂不存在的目标菜单。`enemy-animation-numeric-probe` 和实际 SDL 主循环核对体、气、精神、攻防、等级、经验、攻防计时、四种状态、速度次序及最终选人，六组 128 个完整记录阶段通过。

数值夹具每组仅初始播种一次：三人防御组使用 14，其余使用 4，以匹配采样的随机目标／伤害浮动；行动间不重新播种。生产 LCG、抽取顺序与公式保持原实现。**这不证明原厂随机开机状态、所有路径的调用数量已完整复刻。**

## 显示实现与原指令证据

1. `world_enemy_hit` 在体力扣除前提交敌方 BEGIN／DAMAGE 显示回调。回调编号 7 是 C 内部标识；原厂敌方普通攻击仍是类型 0。
2. `32:E488`／`32:E4D2..E4D8`：敌人临时位置为目标队员 `(x−40,y−10)`。阵型按当前一／二／三人数取原坐标，敌图读取当前 NPE。
3. `32:E69C..E7BE`：清除敌人原来的包含端点的 40×50 矩形后绘制接近图。经 `4E:C498`→`48:0000` 的模式 1 路径调用固件 `03:42C4`；模式 2 则调用 `03:42C8`。本接近分支保留重叠处已有非零像素。三敌夹具曾在 `(104..109,65)` 产生六个差异，修正后全部提交一致；其它模式 1 使用路径仍需各自对照。
4. `32:EC22..EC2E`：接收者向右 2 像素，取受击姿态 1；`32:EF78..EF80` 检查其已排队类型 5，覆盖为防御姿态 4。清除包含端点的 32×40 矩形，队员图含零色覆盖绘制。敌方接近只产生一次可见提交。
5. `30:16E4`／`30:1728`：友方数字基点 `(原x+10,原y+4)`，每次上移 7 像素，使用原厂 5×10 数字、6 像素间距及透明负号；不能复用敌方受击数字的 `y+6`。
6. `31:78DA..7C90` 及队员归位分支恢复敌图／目标。第一次飘字后归位，再做其余两次飘字与底图交替；最后保留重复底图、全部角色刷新、选择刷新、HUD、控件、指针和状态提交。
7. 先受击再攻击场景暴露旧 C 的攻击者归位姿态错误：176／1000 体力被误画为姿态 2，差 591 像素。`31:7DFA..7E20` 识别当前攻击者类型 0／4，`31:7EBC..7EBE` 在一般低体力判断后强制姿态 0。已按通用分支修正；受击者归位仍保留原低体力／防御规则。

`npe_render_battle_enemy_attack_stage` 实现接近／归位，`npe_render_battle_party_damage_numbers` 实现友方数字。SDL 主循环通过既有跨行动缓存调用这些纯 C 服务；生产程序不加载原 PRG、WASM、截图或测试头。临时敌槽／数字字段入战清零，不写入 NPESAV15。
