# NPE 剧情战斗事件驻留表与胜负后继

更新于 2026-10-08。实现使用纯 C11 和 SDL2；编组键与胜负后继来自当前 NPE 装入的共享驻留状态。

## 原装载与寻址

原地图装载器 `29:E3D6..E5C6` 遍历 group8 的四条 11 字节记录，丢弃前两个 word，将编组键、胜利模式、失败模式、胜利事件 word、失败事件 word 重排到 `52:77FC` 起的四个八字节槽：

| 偏移 | 内容 |
| --- | --- |
| 0 | 编组键 |
| 1 | 胜利模式 |
| 2 | 失败模式 |
| 3 | 保留的填充字节 |
| 4..5 | 胜利事件，大端 word |
| 6..7 | 失败事件，大端 word |

有记录的槽保留偏移 3；缺少记录的槽只清编组键，另外七字节保留。`resident_battle_events.inc` 按此规则装载，暖恢复及重新开始沿用相同规则。新增 32 个 World 绑定字节，逐地址计数总计 3508；表尾与选择表 `52:781C` 相邻，非对齐、跨槽及战斗／选择相邻写入进入同一状态。

入口 `39:AF5C..AF8A` 将完整事件 word 减一、按有符号 word 扩展再乘八寻址。C 撤去四槽和低字节限制：已拥有的地址读取 World，其他地址必须属于当前 World 的资源 RAM；不可用地址返回诊断 -2。没有证明全部表外寻址和原芯片异常投递。

## 入场与结算

剧情入场读取实时事件槽，再扫描四条驻留怪物编组记录。原入口默认选择中间敌人，三槽全零也仍进入三槽战斗显示。C 同步该选择规则，SDL 按战斗槽数进入画面，避免中间敌人号为零时误走地图绘制。

原失败后继 `33:BD0C..BD82` 和胜利后继 `33:C50E..C588` 在结算时按当前事件号重读驻留表。C 在失败提示／胜利与升级提示之后重新读取模式及完整后继 word，设置初始化请求；不再把入场缓存作为结算依据。这允许战斗中途对驻留表的修改影响后继。
