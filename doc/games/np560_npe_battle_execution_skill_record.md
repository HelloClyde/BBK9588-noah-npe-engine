# 战斗执行的共享技能记录

更新：2026-10-08。纯 C11 + SDL2 的排队施法、执行和动画渲染接入原共享技能记录；当前 NPE 提供技能资源和角色动画，没有固定游戏名称或技能编号特例。

## 指令与实现

- 源`2F:CFD2`在敌对术动画准备时调用共享装载，读取`7380`动画编号；源`2F:D0FA..D124`的己方准备将效果动画编号清0。源`2D:3CEC`再次装载命令中的技能编号，然后读取`7386/7388/738A/738C`数值。相同编号保持144字节，换编号按既有原装载服务读取NPE。
- 类型、群体和阵营取保存的`64D0/64D3/64D4`，数值、状态词和费用取当前共享记录。`world_run_round`据命令字段判断换目标资格，避免提前读取资源来覆盖选择结果。执行不再次检查已学技能前缀或等级；原效果入口没有这项检查。
- 新增只读`npe_world_skill_view`和`npe_world_battle_magic_view`：在调用者的42字节临时区还原文件顺序视图，后者覆盖命令保存的类型／群体／阵营。渲染器读取视图，不额外装载资源或修改144字节缓存。
- 我方效果入口、动画准备、接收者姿势、浮动数字，以及敌方选技与对应动画／接收者渲染已接入共享记录。源`32:DA56`和`33:73DC`支持敌方入口的装载；同次行动中的重复同编号调用没有重新读取文件。
- 源`35:EF88..F198`及`F6B8..F96C`按首个非零的防御、攻击、气、体词选择浮动数字。修复旧实现忽略气、只显示体的复合回复错误；标签仍按其原判定处理。
- 源`2D:4488..44A4`扣气在应用回复效果之前，没有执行时的气值重检。原诊断气119、费用5、回复气3得到117；本轮保留这一顺序。地图施法的扣费顺序是另一条服务，不能套用到战斗。

合计**7条短战斗、205次实际C／SDL提交**，整屏240×120和ARGB读回零差异；逐路径核对最终缓存编号、144字节及六份人物／敌人记录共66项字段。原RAM采样在推进批次结束时完成，不是每条指令或每次LCD的即时状态。

`tests/sdl_battle_execution_skill_record_probe.c`包含真实`main.c`的`play_battle_animation`和命令恢复渲染，直接调用生产排队／执行服务并实际呈现SDL；此轮的新探针验证执行和动画，不把它当作完整输入控制器测试。列表／目标控制器沿用上轮10条路径33提交的探针。初始场景由生产C构造，未复制参考图给待测渲染器。

最终10目标构建无警告，9项必要短检查通过。除本项外，战斗菜单33、地图技能51、共享技能16和五组生命周期、战斗施法七场景均保持；既有我方六组164动画／252属性阶段，敌方回复四组104／168、伤害三组72／126、状态六组178／252也保持。证据见`tmp/battle-execution-skill-record-report.json`和最终日志。

## 更正和失败证据

1. 初版函数放在命令枚举之前导致编译错误，并留下未用的执行资格函数；调整枚举位置并删除额外资格检查，构建日志保留。
2. 原参考已完成行动，但菜单驻留号是30，不是先前假设的20；扩大到已证实的20／30，不以等待时间解释这一错误。两次失败和RAM终态保留。
3. 一度把扣气误判为效果后扣费，原短战斗明确为117，撤回该改动；没有把115作为期望值写入夹具。
4. 复合回复浮动数字差10像素，补查源`35:EF1A`后改为气优先于体；失败画面保留。
5. 新探针恢复控制页时传错图标编号，差392像素，改为真实底部左侧编号2。该错误在探针调用者，未改原参考或生产控制器。
6. 三个旧敌方动画探针补齐暖重启夹具入口、既有短开场输入和超时退出。原像素及人物断言未改。
