# NPE 随机敌人驻留表与剧情战斗回退

更新于 2026-10-08。继续使用纯 C11／SDL2，按原固件分支实现，未添加游戏专用敌人或剧情例外。

## 八字节驻留表

原装载器 `29:CC60..CD28` 读地图尾部偏移 644 的八字节，每次先清当前目标槽，再把非零字节写入紧凑索引。装载结果是原顺序的非零前缀及零尾部；装载不按有符号数过滤。C 将结果绑定到 `52:7916..791D`，和前面的学技表连续，总 World 绑定由 3508 增至 3516 字节。

地图初始化、换图、暖恢复和重新开始装载该表。普通行走遭遇也读取驻留表；运行时修改会影响后续编组，不再重新从 NPE 文件解析原列表。运行时直接注入零洞时，战斗服务在第一个零处停止，和文件装载压紧非零项的规则不同。

## 编组无匹配时的回退

原 `39:AE64` 先清三个敌人记录的当前体力，再按剧情编组键扫描四个怪物槽；无匹配进入 `39:B08E`。C 接通该回退，不再因找不到编组键立即报错。

| 条件 | 原分支与本次实现 |
| --- | --- |
| 上下文 word 按有符号数大于零 | 数量置 1；从 `52:7840+14*(context-1)` 读敌人 word 到首槽，另两个敌人号清零 |
| 上下文零或负值，随机表前缀为空 | 保留入场前的三个敌人号和剧情入场数量 3 |
| 只有一种随机敌人 | 数量置 1，仅改首槽；另两个敌人号保留 |
| 两种以上 | 原共享生成器决定数量及索引；仅改实际数量内的敌人号 |

多种敌人时，第一次 `%100` 小于 10 取三敌，小于 30 取双敌，其余取单敌。后续索引保留原重复敌人分支及越界重抽。`39:B398..B3B8` 在首、次索引相同时使用 `100/(3*当前编组数量)`；此时数量为 3，阈值为 11。旧 C 注释与实现误写为 `100/(3*可选种数)`，本次修正，普通遭遇使用同一算法。

剧情默认目标仍是中间槽，回退数量为 1 时也不在入口主动改成首槽；原公共参考保存的联合目标为 2，对应 C 敌人索引 1。实际行动选择和其后的全部退场行为另需核对。

追击上下文按完整 word 寻址，未加两个槽的限制。本次上下文 3 在 `52:785C` 的表外资源 RAM 读到注入敌人；资源 RAM 必须属于当前 World。原随机字节会符号扩展，原追击敌人号是 word；C 当前敌人 ID 模型尚不能表示所有负值／高 word，遇到这些值给出诊断而不截断。本次没有证明原异常行为。
