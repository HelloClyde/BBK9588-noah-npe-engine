# 围攻／联合的指令准备与目标状态

更新：2026-10-09。实现是纯C11，资源来自当前NPE，显示／输入由SDL2提供。QEMU和原前端仅用于开发对照。

## 原版规则与实现

`npe_world_battle_prepare_group`和`npe_world_battle_prepare_combine`从实际行动中拆出，共用物理记录读写；生产围攻／联合调用它们后进入原有速度队列。不是另一个仅供检查使用的规则实现。

| 行为 | 原版位置 | 实现 |
| --- | --- | --- |
| 围攻确定目标 | 44:8B94..8C3A | 从队伍前缀人数＋1开始，检查物理体力是否非零；负word同样满足，不使用有符号正数过滤 |
| 围攻空前缀 | 同上 | 数量0仍检查首槽；全部为零时保留最后检查的目标，不在准备阶段直接拒绝 |
| 围攻写人物记录 | 44:8C44..8E66 | 重写每个队伍前缀记录，包括倒下／睡眠成员；目标统一，指令4，类型两字节清零，类型副本1，群体0，阵营0 |
| 围攻全局状态 | 44:8BB6／8BCA、8E78、8EC2 | 发布物理目标，旧指令取首记录，当前角色置队伍人数－1；人数0的字节回绕为255 |
| 联合写人物记录 | 49:8178..8330 | 每个前缀记录指令3、目标人数＋1、类型副本1、群体1、阵营0；保留原64D0／D1和独立物品／仙术编号 |
| 联合全局状态 | 49:8342／8354 | 从首物理记录发布旧指令及目标；保留当前角色 |

此前C围攻准备只写能行动的人。现改为先重写全部前缀记录，执行阶段再跳过不能行动的人；宿主待执行队列和原版驻留记录继续独立。联合此前没有更新共用群体／阵营字段和全局目标，本批接通。

**尚未覆盖的全局状态：** 围攻原函数还发布7AA6、7AA0、7AAA三个word，本批没有把它们绑定进World。因此本批证明的是六份完整人物记录及所列三个全局字节，不是整段128KiB RAM全部等价。

World仍绑定3537字节，`save.c`及NPESAV22载荷保持。原机存档互通、正常属性完整通关、SDL全程实玩继续取消。

## 原函数准备对照

新脚本直接执行原44:8B94和49:8178..8354的写记录指令与原函数尾声。所有原写记录指令及乘法服务字节都与原PRG核对；联合8358的后续辅助调用由诊断NOP跳过，避免键盘／IO依赖，不把该调用计作已验证。

18组诊断输入包含人数0～3、负体力65535／32768、首／中／末敌人、数量0／1／2的空前缀、全部敌人体力0、倒下／睡眠成员、围攻后联合、联合后围攻及各自重复调用。输入记录填入不同保留字节，能检查未参与的槽和独立编号是否被误清。

原函数与生产C准备函数的六个148字节物理记录全部一致，共108份；当前角色、旧指令、全局目标共54个字节一致。C同时核对World及实际资源运行时的同一记录视图，原函数堆栈返回完整。原完整128KiB RAM也保存为证据，但C只比较上述记录／控制字段。

这里的人数／数量0是准备函数局部检查，没有执行异常入战／完整回合；数量255及物理槽外访问仍未完成。

## 公共输入与SDL对照

沿用六条原围攻路径的`displayTarget`观察，加入两路C／实际main的目标检查；包括单人、两人、首敌人被击倒、速度顺序、睡眠／倒下和覆盖已排队防御。新增36份全局目标快照一致，既有13次围攻行动、153次C与153次SDL动画提交及六幅结束画面保持。

联合原公共脚本增加独立`--selector-target`输出，不覆盖已有参考。六条单轮及两条连续两轮路径，共八条／十轮，新增56份两路目标快照一致。去掉新增观察字段和文件名后缀后，事件记录与旧参考一致；新旧280幅行动LCD及28幅输入状态画面逐字节一致。既有16条联合数值路径／18次行动、18幅实际SDL结束画面和10段C／SDL动画保持通过。

上述旧数值探针比较指定属性、状态和顺序，不能把它们的111／309个属性记录阶段称为完整148字节记录；完整记录证据是前述108份。

## 修复和最终检查

- 联合旧夹具入战后只改宿主敌人ID，物理图像word仍来自原空槽，首帧出现2537像素差异。现按原公共输入在入战前设置编组；原画面和数值断言保持。
- 旧围攻完整main检查只拦截冷启动，新游戏现在走重开入口，导致按键落到地图。补上实际重开入口的相同诊断构造器。
- 该旧检查的双目标剧情场景沿用早期压紧敌人槽的假设。现先从当前NPE驻留编组读取中心ID，入战前复制到左槽，明确构造其双目标诊断；剧情默认中间目标已经是非首目标，省掉会切回首目标的Tab。保留原“执行前目标1、围攻重置到0、只有共同目标受伤、人数和速度顺序”断言。六条原公共围攻输入不变。
- 首次原采样完整RAM请求超过接口单次大小；改为四块读取后合并，失败日志保留。
- 首次独立汇总已比较完成，但报告写入因Path字典键无法JSON序列化失败；转为路径字符串后通过。

50目标构建无警告，49项必要短检查最终全部退出0。生产代码在整批期间保持；旧围攻检查修复后只重建／重跑该失败项，其它48项本批结果保留。独立汇总重新读取记录、全局目标、原画面和前批保存输出，检查新结果时间与原资源／存档源码哈希。
