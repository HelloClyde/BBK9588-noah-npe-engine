# NP560 NPE 投掷预扣、取消与角色返回

日期：2026-10-06。C11 / SDL2 实现；原厂 WASM 仅用于采样。

## 原厂证据

采样脚本 `tmp/battle-native-item-reservation.mjs` 从原厂战斗快照恢复，复制完整人物记录到
独立双／三人夹具，增加原 NPE 敌人 51 的编组槽，并提供原 NPE 飞刀 159 的背包数量。
人物体力／速度是独立诊断属性，敌人的 NPE 记录未编辑。
这些是隔离的规则夹具，不是连续主线存档。

`52:67C8 + 2 * item_id` 是背包 BE 数量，`64D5 + 148 * actor` 是本行动所选道具。
原厂在进入菜单 37（投掷选敌）前就扣一件，而不是动作结算时扣除。
菜单 37 的 F4 路径 `36:E1A0..E2C4` 加回背包数量并回到列表 33。
基础图标页的 F4 路径 `36:DBE0..DEDE` 回到前一名可行动角色，退还被取消的道具；
跳过倒地／睡眠／封印角色时不退还那个被跳过角色的道具。

| 独立原厂轨迹 | 初始数量 | 观察结果 |
| --- | --- | --- |
| 双人选择飞刀，取消选敌，重新选择，再取消 | 1 | `1 → 0 → 1 → 0 → 1` |

## C / SDL 修改

- `NpeWorld.battle_item_reservations[3]` 保存每名角色已扣除、尚待处理的投掷道具。
- `npe_world_battle_reserve_throw_item` 读取当前 NPE 类型／伤害，扣一件并记录。
- SDL 道具确认后先预扣，再显示选敌；F4 取消、窗口退出或提交错误时退回对应选择。
- `npe_world_battle_throw_item` 确认已有预扣时直接排队；直接调用规则 API 时也先扣再排队。
- 执行已预扣的投掷允许库存为 0，消费其预扣记录，不重复扣除。
- 回合结束、胜负或覆盖后的丢弃清理不会返还道具，保持上表观察到的原厂结果。
- `npe_world_battle_previous_actor` 回到上一名可行动且已选命令的角色，返还其预扣，清除命令。
- SDL 基础图标 F4 接入上述返回；没有前一人时回默认攻击图标。
- 再次打开使用／投掷子菜单，保留原来的投掷选中项，不强制改回使用。

本次只实现投掷预扣。普通战斗道具的预扣与多人友方选人／结果仍待处理。

## 保存与恢复

既有 `npe_world_save` 仅允许地图模式 1，战斗模式 3 的未提交选择和排队命令不能保存。
不引入战斗存档，也不将临时资源指针写入文件。

探针验证：选择中和排队期间保存失败且不改数量；胜利回地图后，已消费数量以原有
`NPESAV14` 保存／载入，数量为 0，预扣和排队状态清空。没有改变文件布局或版本。
这项是 C 存档一致性检查，不是原厂二进制存档格式的兼容证明。

## 同时修正的基础图标导航

`tmp/battle-native-icon-grid.mjs` 对照基础图标的方向键与 F4。
原厂不在边缘循环；仅一个存活角色时不能选右下图标，两名存活角色时可以。
第二人倒地会禁用该图标，第二人睡眠仍可选。
右下图标的确认动作依然未实现，不能以导航完成代替其功能验收。

`npe_world_battle_move_icon` 与 SDL 主循环按此处理。
一人、两人、第二人倒地各 25 张整屏逐像素一致，共新增 **75 张**；
第二人睡眠另外验证 25 个菜单选择值，不将未完成的状态覆盖图计为像素验收。
菜单选择值在 `tests/battle_icon_grid_native.h` 中来自原厂实际记录。
与旧 99 张合计 **174 张整屏零差异**。
