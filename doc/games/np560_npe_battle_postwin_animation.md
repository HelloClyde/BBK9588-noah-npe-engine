掉落夹具使用原 NPE 物品 48／50，在隔离敌槽设置这两个候选，以核对原厂通用显示。它们不宣称原敌人 51 实际会掉这些物品。生产代码只使用当前敌人记录的两个掉落字段，不按敌人或物品 ID 特判。

本次共核对 **14 张升级面板、6 张修炼提示和3张掉落提示**。C 与实际 SDL 比较每次完整显示；每个操作阶段比较全体六条记录的体／气、属性、等级、经验、状态与计时字。原厂掉落画面提交时的库存也独立核对：单候选为 1／0，双候选在第一张提示之前已为 1／1。验证发生在离场复制之前，没有把离场后的旧战斗地址当成地图背包证据。

## 原厂显示顺序与资源

`33:C27E..C286` 的顺序是奖励、掉落、升级。升级函数随后逐次调用新学仙术提示，最后再清理战斗记录、恢复战后体力并进入后续事件。

1. **掉落：** `39:40AE..4706` 先完成所有物理敌槽的概率、候选名称收集和库存更新；`39:4718..4890` 再显示。当前 NPE 第一 UI 图组基址 +31 是“得到”面板，坐标为 `(40+20×敌槽,30+20×敌槽)`，名称放在其 `(48,8)` 偏移。第二候选在同一位置重画；空敌槽仍影响后面面板的坐标。
2. **升级：** `2F:A628..A670` 使用第一 UI 图组基址 +33，坐标 `(10+25×有效角色序号,14)`。死亡或入函数时已达 99 级者跳过；同一人连续升级复用同一个位置，序号在其结算结束后才递增。未升级但符合处理条件的角色仍占序号。
3. **面板字段：** 名字取当前角色记录，原图中的英文标签保留。旧／新等级、体力、气、攻击和防御按源坐标输出；体／气显示当前值与上限。文字透明绘制，保留原厂长诊断数值与箭头重叠的像素，不进行美化。新体／气列偏移是 90，其他新值列为 106；数字使用原厂 5×10 字形。
4. **修炼：** `2F:B782` 调用 `43:C174`。先扫描十八项有序仙术槽，跳过要求等级低于当前等级的部分，然后只显示连续的同等级仙术。原图为第一 UI 图组基址 +32，位置 `(36+8×队员序号,40+14×本次新仙术序号)`；名称来自当前技能记录。面板保留此前奖励／升级内容。
5. **输入与等待：** 提示自动等待，不要求按键关闭。原厂掉落／升级等待参数为 80，修炼为 50；SDL 暂按毫秒使用。固件真实时间单位尚未核对，画面一致不证明时长已经复刻。

三个新的内部显示事件只传递角色、面板序号、敌槽／候选或技能字段；不是新 NPE 指令，不修改 NPESAV15。

## 同步修正的数值行为

- 成长路径先保存 16 位加法低字，再用带符号比较限制 999；不能把 65535+5 用宿主大整数直接封顶。七项成长统一采用该源规则。独立夹具证明体力上限 65535→4→9，而非 999。
- `2F:A562` 在 `A61C` 的 99 级检查前已经扣除经验门槛。本轮达到 99 级后若经验仍够，仍会重复扣门槛，但不增加等级、不显示新面板。入函数前已经 99 级者仍由 `A55A` 跳过。独立原厂输入确认 40045→40044→9164。
- `38:E182..E216` 在胜利清理时把基础攻击／防御同步到当前战斗记录。C 此前只增加基础防御，留下旧的当前防御；本轮修正，全部完整记录对照通过。
