# 仙术／道具选择器的战斗资源生命周期

更新：2026-10-09。实现位于 `npe-sdl/main.c`，使用已有纯C堆和NPE资源服务；运行不依赖原固件或参考前端。

## 本批实现

仙术和道具列表现在接入原版打包战斗图像缓冲的释放／重新装载流程。缓冲内容来自当前NPE，不是屏幕截图。公共辅助函数 `battle_resources_set` 同时供战斗查看状态使用。

| 输入位置 | 原固件位置 | C／SDL操作 |
| --- | --- | --- |
| 进入仙术列表 | 4E:06F4..071C | 解锁，重读句柄并释放，清52:7AA4 |
| 有效仙术确认 | 3A:0CFE..0D3E | 分配32768字节、锁定、发布指针、置标志、读取当前NPE打包资源 |
| 仙术目标取消 | 36:E01C..E052 | 释放资源后回到阶段21 |
| 仙术列表取消 | 36:E07A..E0BA | 重新装载后回到战斗按钮 |
| 进入道具列表 | 42:8EDE..8F14 | 释放资源后进入阶段33 |
| 有效道具确认 | 38:4CEA..4D2A | 重新装载；群体／单一目标同样执行 |
| 道具目标取消 | 36:E1B0..E270 | 先释放资源，再退还道具，再写阶段33 |
| 道具列表取消 | 36:E2D8..E318 | 重新装载后返回使用／投掷菜单 |

以上操作按原调用点执行，不用“标志已经相同”省略堆服务。释放保持发布的句柄和指针，只清资源标志的高字节；低字节保留。无资源运行时的专项规则测试仍同步World标志，实际游戏使用附着的C资源运行时。

本批没有增加World绑定，仍为3536字节；没有修改 `save.c`，自身存档仍为NPESAV22。

## 原版参考与验证

两个已有原公共输入脚本新增 `--resources` 模式，使用独立输出文件，保留原10条仙术／11条道具参考与头文件。新增模式只增加诊断输入低字节A6和资源标志观察，以及六条额外输入路径；原固件／前端和NPE均未修改。

覆盖取消、换选项、目标切换／取消、群体排队、重新读取缓存、等级与气不足拒绝、空列表、空道具255别名、投掷、翻页、反复进入目标选择和确认目标。

| 对照 | 原公共路径 | 实际SDL菜单提交 | 控制／缓存快照 |
| --- | ---: | ---: | ---: |
| 仙术 | 13 | 73 | 108份，含完整144字节仙术缓存 |
| 道具 | 14 | 96 | 139份，含完整142字节道具缓存 |
| 合计 | 27 | 169 | 247 |

每次提交同时比较C的240×120像素和SDL读回像素；每份快照检查菜单阶段、当前角色、完整52:7AA4／7AA5资源word及缓存。列表阶段为00A6，目标选择／取消回战斗菜单／确认排队后为01A6。探针附着实际NPE资源运行时，检查共享word和运行时错误计数；其它既有命令、库存、属性断言保持。

本批执行生产 `main.c` 中的菜单函数。外层控制器的157次原版LCD提交未纳入这两个菜单探针，不能将169次菜单提交描述为完整外层控制器对照；其它已有实际main／SDL短路径作为必要回归执行。

前批五组原堆／打包装载服务参考再次运行并逐字节复核：每组完整128KiB RAM和18字节读取记录一致，包含重复装载、短读、EOF、最终释放和句柄0。这些服务参考使用诊断调用者和文件适配器，不代表完整原机启动RAM已等价。

最终37个目标构建无警告，36项相关短检查全部退出0。独立汇总重新读取保存的169幅C画面、247份状态快照及五组服务RAM／读取记录，并检查本轮输出时间、原资源哈希及保留文件哈希。

## 修正与保留的失败证据

- 首次构建在新探针中用了不存在的记录／图像字段名，已改为真实的 `battle_record_residue` 和 `NpeEnemy.graphic`；失败日志保留。
- 两个旧菜单夹具只修改敌人查询ID51，未同步物理敌人图像word46／47。现从当前NPE的敌人51读取图像号，匹配原参考入战编组；旧参考与原断言保持。
- 新增敌方目标确认暴露旧仙术探针把“确认后换角色”与“取消回按钮”共用目标偏移判断。按原快照保留的物理敌人目标修正判断；确认前全部画面和资源状态已经一致。失败日志保留，原参考数据保持。
- 道具取消的生产顺序调整为原版释放、退款、写阶段33，最终整批重新构建和执行。
