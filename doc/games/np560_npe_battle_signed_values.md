# NPE 战斗气值、普通攻防差与低字回绕

更新：2026-10-06。实现依据为原厂 PRG 与独立原厂输入采样；规则不按游戏或物品 ID 特判。

## 仙术选择与执行

源 `3A:0834..08AC` 读取费用 `738E` 和当前行动者 `64A4`，以带符号比较判断费用是否小于等于当前气。列表可以在负气时打开，确认才显示原“气不足”提示。被拒绝时没有排队、扣气或敌方行动；确认维持提示，Cancel 只取消提示，F4 返回战斗图标。

源 `2D:4488..44A4` 执行已排队仙术时直接扣除费用低字，没有再次检查费用。另一行动改变当前气后，已选仙术仍执行。这与负第四状态只阻止选择入口的规则一致。

原厂列表及体／气数字使用带符号十进制。`65535` 显示为 `-1`，`32768` 显示为 `-32768`；原厂负号是第六行四个像素，保留第五列空白。列表右下数值区域只容纳七个完整字符，长负值按原厂边界截断。

`tmp/battle-native-negative-qi.mjs` 的九条输入包含：

| 当前气 | 费用 | 原厂结果 |
| --- | --- | --- |
| -1、-32768、0、24 | 25 | 打开列表；确认提示不足；无数值或命令变化 |
| 25 | 25 | 执行后气 0 |
| 0 | -1 | 执行后气 1 |
| 0 | -32768 | 执行后气 -32768 |
| -1 | -1 | 执行后气 0 |
| 选择时 500，排队后独立改为 0 | 25 | 仍执行；气 -25，另一队员气 475 |

测试生成器 `generate_negative_qi_native.py` 固化九条原厂参考。C API、C 索引画面及实际 SDL 列表／确认／重复确认／取消／返回均通过；对照两阶段体、气、四状态共 **74 个记录阶段**。SDL 读取实际绘制后的 framebuffer，按程序 LCD 色板比较。HUD 只比较其数字区域，不计整屏。

九个列表和四个不足提示中，排队样本列表与已有封术入口参考相同；新增 **12 张不同整屏零差异**，累计 **317 张**。重复确认与取消的重复画面、C／SDL 同一参考不重复统计。

## 普通攻击：角色与敌方分别实现

角色源 `2D:3944..3952` 保留攻防差及倍率乘积低字，再以带符号值比较下限和上限。本轮全部夹具将双方 `64AA` 字段设为 1，因此倍率为 1；后续已接入完整属性倍率，见[带符号除法与回绕](np560_npe_battle_attribute_multiplier.md)。

角色公式顺序为：

1. 截取攻防差低 16 位，解释为带符号数。
2. 下限为行动者等级／5＋4，上限为 996。
3. 加一次 `随机值 % 6 - 3`。

因此不能先把攻击字单独解释成负数，再用 32 位攻防差比较。例如 `32768 - 45` 的低字是正的 `32723`，原厂仍走上限；`65535 - 45` 的低字为 `-46`，原厂走下限。

敌方源 `33:7088..70A6` 则先加浮动，再保留倍率乘积低字；**这里没有原先文档写的 999 上限**。`70FA..715A` 在伤害小于等于等级／5＋8时写入下限，并直接跳过防御分支。高于下限才检查目标是否选择动作 5，`71F2..720C` 截取乘 25 的低字、带符号除以 100。`7234..723C` 最后再加一次同一个浮动。

原厂各控制样本确定角色浮动 -3、敌方浮动 -2。C／SDL 夹具种子 4复现这两个抽取结果，**不表示已还原原厂启动 RNG 状态**。

| 原厂独立输入 | 结果 |
| --- | --- |
| 角色攻 -1／敌防 45，等级 10 | 敌体 30000→29997 |
| 角色攻 -32768／敌防 45 | 敌体 30000→29007 |
| 角色攻 60／敌防 -1 | 敌体 30000→29942 |
| 角色攻防差两端回绕 | 两组均扣 3 体 |
| 角色攻 1200／敌防 0 | 原上限仍扣 993 体 |
| 敌攻 -1／角色防 13，等级 10 | 角色扣 8 体 |
| 敌攻 -32768／角色防 13 | 角色体 32767→16 |
| 敌攻 60／角色防 -1 | 角色扣 57 体 |
| 敌攻 1200／角色防 0 | 角色扣 1196 体，不夹至 999 |
| 已选防御，敌方走下限 | 仍扣 8 体 |
| 已选防御，敌攻 1200／基础角色防 0 | 行动后防 100、计时 1；扣 272 体 |
| 已选防御，敌攻 1600／基础角色防 0 | 原待结算字 -282；角色体 1000 保持，不回血 |

`tmp/battle-native-signed-attack.mjs` 导出 17 条输入。循环恢复会迁移原厂 RAM，因此仅将已采完的退役夹具签名清零，下一次恢复仍要求唯一 RAM 候选。最早全批次在负攻击样本因夹具体不足终止，只有已完成七条角色参考被保留；九条敌方以体上限 32767重新采样，另取一条体 1000 的乘法回绕参考。最终生成器只使用这三份完成的 JSON，不采用失败批次的敌方结果。

`sdl-signed-attack-probe` 对照入场和行动后 **136 个记录阶段**，包括体、气、当前攻防、两个计时字及四状态。14 条普通攻击和 3 条防御均走实际 SDL 主循环按键；防御经旗帜菜单选择第三行，不通过辅助 C 调用代替。另有同参考的 C 规则对照，不重复计数。
