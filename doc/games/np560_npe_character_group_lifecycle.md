## 源码和原执行证据

- `2E:82CE..831C` 的人物文件装载，把当前 NPE 字节 `raw[79]` 写到地图 `69F2 + 148×槽位`。
- 入战复制地图人物记录到 `6450`，群攻字段成为 `647C`；剑图标 `40:1B44..1B80` 再复制到命令 `64D3`。每次选攻击重新读静态 NPE 会丢掉驻留变化。
- 成功逃跑的 `2F:C1E2..C24E` 按入战前缀复制每个人物全部 148 字节回地图，包含群攻字节。C 共用离场服务在恢复地图原队伍标记前复制此字段。
- 队员离队服务交换同伴人物记录，群攻字段必须与 ID 一同移动。C 共用 `world_swap_party_slots` 现在包含这个字段。

原侧从独立暖战斗快照经实际地图／入战派发和按键逃跑；只注入隔离 RAM 的地图群攻／队伍／体力，以及战斗群攻字段。成功退场后再次入战；三人例另派发原模式 10 的二号队员离队事件。原 NPE、PRG、快照文件和随机服务保持原样。

原 JSON 包含入战前、入战后、战中改值、退场、换人和再入战的批次 RAM 状态，另存 12 张入战 LCD。新增后端探针核对字段，不将这 12 张计为新增 C／SDL 整屏覆盖；像素回归沿用已采集参考。

## 自身存档

新增 `party_attack_groups[3]` 保存地图字段；`battle_attack_groups[3]` 是独立战斗副本，选择期间读后者，保存读取前者。

NPESAV19 在 payload 偏移 1376 的五个保留字节编码 `47 50`（GP 标记）及三个人物群攻字节。文件长度、所有后续字段位置和校验方式保持不变。旧 V19 没有标记，恢复时按存档人物 ID 从当前 NPE 补值；V18 及更早版本仍把五个字节作为旧答题会话字段消费。新版不把它们恢复到答题会话。旧 V19 读档代码会跳过新增数据，不宣称旧构建能保留新增群攻状态。

四组保存序列覆盖冷读取、暖恢复、战斗副本与保存字节隔离、旧 V19／V18 恢复、暖新游戏重置和损坏文件恢复的事务性。额外独立内存 NPE 夹具给三个人物设置不同群攻值，验证旧档人物 ID 3/1/2 真正恢复 255/1/2；没有修改原磁盘 NPE。自身存档验证不是原机存档互通，后者保持取消。
