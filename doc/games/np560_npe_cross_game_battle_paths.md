# 跨NPE战斗、保存与冷读取短路径

更新：2026-10-10。本批增加可重复的诊断入口，未修改生产引擎规则。

## 范围与结果

对现有18份NPE各选择一个可执行的战斗场景，使用当前文件的人物、敌人、技能、位图及战斗事件，执行生产C与SDL函数。18份全部通过，共1600次实际SDL画面提交；每次SDL输出与C索引画面一致，运行时未记录不支持的操作，内存中的NPE指纹保持不变。

| 路径 | 结果与检查内容 |
| --- | --- |
| 入战 | 15份调用当前NPE的剧情战斗；天降风云xab、新仙剑后传、英雄传奇走实际移动遇敌服务；四阶段入战画面均提交 |
| 防御及敌方行动 | 18份执行防御、敌方回合及实际动画 |
| 技能 | 我的世界、阿诺创世纪额外执行各自初始队员已有的技能及选择页 |
| 胜利与后继 | 18份执行攻击获胜；胜利模式／事件按当前NPE记录检查，再经实际SDL事件分派返回地图 |
| 自身存读档 | 战后保存，关闭资源运行时，解码保存状态，再重新装载资源；地图、剧情、坐标、视口、金钱、队员属性、装备、技能、状态与条件字恢复一致 |
| 再次入战 | 冷读取后绘制地图，再次进入同一诊断战斗或普通遇敌，检查敌人数、活动角色及四阶段入战画面 |

天明各版本的胜利后继调用物品服务，异域各版本调用进度事件，新月奇缘、诺亚论剑等经过对白事件；均使用当前资源记录。普通遇敌通过诊断步数和固定种子缩短等待，并未改写地图资源。

## 验证边界

- 按用户已授权的方式提高诊断角色的生命、气、等级及攻击，缩短战斗；没有验证正常属性通关。
- 每份只覆盖一个选择出的战斗场景，场景由诊断入口直接初始化；没有证明剧情能自然到达所有战斗，也没有验证全游戏连续战斗与队伍组合。
- 1600次比较是SDL输出与本引擎C画面的一致性检查。本批没有这些游戏的原机逐像素参考，也没有打开音频设备。
- 资源关闭／重新装载覆盖冷读取路径，但本批在同一进程内运行；跨进程冷启动已有此前的独立检查，本批不新增该结论。
- 当前候选音频解码器仍缺少同一NPE的可信原PCM参考；前端独立WAV素材不能作为该压缩流的原声证明。

## 重复运行

诊断入口：`npe-sdl/tests/sdl_cross_npe_battle_probe.c`，直接包含生产`main.c`并包裹SDL输入、虚拟时钟与画面采集。运行脚本为`npe-sdl/tests/run_cross_npe_battle.py`。主程序不依赖这两个文件或Python。

在已有SDL2及CMake配置的工作区执行：

```powershell
cmake -S npe-sdl -B npe-sdl/build
cmake --build npe-sdl/build --target sdl-cross-npe-battle-probe
$env:PATH = 'C:/msys64/ucrt64/bin;' + $env:PATH
$env:PYTHONIOENCODING = 'utf-8'
& 'D:/ProgramData/miniconda3/python.exe' npe-sdl/tests/run_cross_npe_battle.py --directory 'D:/Downloads/NP560plus游戏全集' --output tmp/cross-npe-battle/final
```

本批中途发现的失败来自诊断入口：未提供普通遇敌备用入口、未设置生产SDL的延迟事件分派标志、误以为存档解码会自动装载资源。入口已按生产调用顺序修正，未据此改动游戏规则或存档实现。
