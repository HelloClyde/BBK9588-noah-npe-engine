# 跨NPE重复交谈、返回旧地图与原NPC条件对照

更新：2026-10-10。生产引擎未在本批修改；本批补齐检查路径并取得其它NPE的原事件／条件函数参考。运行程序仍为独立C11＋SDL2。

## 检查路径

新增 `sdl-cross-npe-branch-probe` 包含实际 `main.c`，从当前NPE原标题／新游戏开始，以普通SDL按键推进。允许提高人物属性以缩短战斗；不注入剧情、NPC条件、库存或资源后继。

- NPC预测仅在256 KiB驻留状态副本和当前NPE原字节上执行，不写实际运行时，也不改变文件游标／读取计数；规划结束核对实际World及IO状态未变。
- 按动作索引、条件成功／失败、对白指针及后继区分重复交谈。到达NPC后从实时状态重新预测，实际入口核对对白、后继和NPC状态。
- 新NPC／行走分支之后允许再次经过旧出口，优先尚未走过的边；每个阶段限制重复出口，最多64次入口及后继检查。这仍是局部路线选择器，停止为exhausted不代表不存在其它游戏路径。
- 原移动使用实际视口坐标。《我的世界》地图10出生输入(10,20)，原视口偏移(3,13)、屏内(7,6)，实际行走原点(10,19)。探针改用视口规划；未改写实际出生坐标。
- 遇到资源模式7／21返回标题、另一选项可继续时，以左右／确认键选择继续。《诺亚论剑》地图9选择事件1的两项是模式2／NPC16与模式21／事件1，不将模式21的资源结束误判为战斗失败。
- `escape failed; mode N, HP N` 是主程序正常逃跑反馈，汇总只精确排除此格式；其它cannot／unsupported／failed／assertion错误仍拒绝。

## 未修改原函数对照

从实际C／SDL路径采集NPC装载前后的驻留RAM。原函数采样先以诊断传输恢复装载前状态，并逐字节确认全部256 KiB已经恢复，再执行原函数。原函数没有使用C结果计算分支；每次正常返回、栈恢复，无缺失ROM、不支持指令或非法控制报告，23次分段读取和2次定位与原文件位置一致。

## 失败记录与范围

- 旧路线全局跳过已走出口，可能漏掉返回旧地图后的新分支；新增阶段和新边优先级后扩展可达检查范围。
- 旧探针在地图10因调整前出生y等于高度停止，原坐标切片确认后只修正探针起点。
- 诺亚论剑原资源模式21结束由普通按键选择另一分支继续；原结束行为没有改成其它结果。
- 汇总器曾将一次正常逃跑失败反馈记为错误；实际程序退出0并完成后继，现保留旧报告并精确修正归类。
- 原函数采样器初稿的批量状态复制未恢复所需RAM，被原定位序列检查拒绝；随后改用诊断传输，恢复前后256 KiB完整检查通过才执行原函数。`native`、`native-first-fixed`失败目录与初稿保留，不计参考通过。
