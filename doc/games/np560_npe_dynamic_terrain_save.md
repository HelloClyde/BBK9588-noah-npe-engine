## 原因与实现

此前NPESAV22保存53个地形索引／图块对及声明槽的应用标志。运行时现在直接执行原地址地形服务，192字节地形表可被共享内存写入修改，地图网格也可累积超过53个改动。旧保存投影无法完整表达这些状态。

修改前的独立探针证明两个问题：改写记录冷读档后有5字节丢失；改写实际网格后生成的槽冷读档返回失败。基线源文件及二进制保存在`tmp/dynamic-terrain-save-before/`，原始失败为`tmp/dynamic-terrain-save-baseline.log`。

当前写出规则：

- 常规状态能由旧投影表达时仍写NPESAV22。最终探针2362字节的常规槽与修改前逐字节一致，SHA256均为`ce85beaeedfc8f9510564c2fabdc71d159104010cc5242d0b1f556af588ab9f6`。
- 完整地形记录、实时尺寸或网格不能由旧投影表达时写NPESAV23。保留V22前缀，再追加尺寸、完整192字节记录及逻辑网格；接受旧V1～V22的读取路径仍保留，本批没有逐个重新验收全部历史版本。
- 当前地图资源绑定有效时，从实际运行时读取网格，不依赖53对观察记录；达到53对后不再因宿主投影容量使原周期更新失败。
- 冷解码先保存地形快照；打开实际资源后执行原网格／物件／地形装载，再叠加自身快照、恢复尺寸并刷新105格缓存。没有序列化宿主指针或客机堆地址。
- 暖恢复沿用已有战斗区和随机会话规则；地形记录及逻辑网格恢复到槽内状态。

新增字段是自身格式的恢复载荷，不增加客机驻留绑定地址；World绑定仍3748字节。

## V23追加布局

| 字段 | 大小／编码 |
| --- | --- |
| 实时宽、高 | 各1字节 |
| 逻辑格数 | 2字节，小端 |
| 三份地形记录 | 192字节，保留原字节图像，包括非布尔标志及尾部 |
| 逻辑网格 | 每格2字节，小端 |

追加长度为`196＋2×格数`。格数对应原宽高乘积低word的有符号结果：非负保留，负结果记0。读取时校验尺寸与格数一致；原有整槽长度、指纹和校验和仍生效。

## 本批验证

### 自身保存恢复

`dynamic-terrain-save-probe`使用当前NPE地图108：

1. 单独改写地形阈值、非布尔标志与填充，核对冷读档的全部192字节。
2. 五轮执行生产周期地形服务，每轮三槽各15格，共225个不同格；宿主投影仍最多53对。
3. 额外直接改写最后一格，不经过观察记录。
4. 核对450格完整网格、全部192字节、冷／暖恢复及打开资源后的实际网格。
5. 冷解码绘制、打开实际资源后绘制均与保存前的自身画面一致；冷重存与原V23槽逐字节一致。
6. 暖恢复前注入888字节战斗区及随机状态，确认二者保留。
7. 格数错误、截短、追加垃圾、错误NPE指纹四种槽均拒绝；即使重新计算校验和，目标World也不改变。

最终日志：`tmp/dynamic-terrain-save-final-dynamic-terrain-save-probe.log`。这些是自身格式的状态恢复检查，未使用其像素作为原机LCD参考。

### 实际SDL启动

`sdl-dynamic-terrain-save-probe`将生成的V23槽放入隔离临时槽，通过实际main的`--continue`入口启动。核对实际资源所有者、地图108的堆网格、192字节记录和首次SDL提交。C索引画面及SDL读回画面都与保存前自身画面零差异，随后退出。

使用SDL dummy驱动，固定时钟并关闭音乐、抑制该短路径的巡逻，以隔离地形恢复。没有全程手玩或原音频时序结论。最初探针误断言音乐属于槽载荷；音乐实际为会话设置，修正探针后通过，失败日志保留。未修改生产音乐规则或参考画面。

最终日志：`tmp/dynamic-terrain-save-final-sdl-dynamic-terrain-save-probe.log`。

## 仍未完成的范围

本批恢复完整地形表与已采样地图的逻辑网格，未恢复整个客机RAM、堆布局或所有文件／资源状态。负索引、奇地址别名、网格之外的写入、负乘积时的残留缓存及尺寸异常仍不能据此宣称任意状态冷恢复完成。加载后的直接内存改写若只关闭再重开资源而未保存，其快照生命周期也尚未核对。

继续完整共享内存写入者／生命周期与保存恢复、原声解码／文件服务、其它NPE动态运行。原机存档互通、正常属性完整通关、SDL全程手动实玩按用户要求排除。
