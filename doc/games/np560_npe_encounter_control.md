# NPE 遭遇控制 word 与运行时地址绑定

更新于 2026-10-08。纯 C11／SDL2 接通两处原控制 word；未添加游戏专用开关。

## 控制规则

| 驻留地址 | 内容 | 原指令规则 |
| --- | --- | --- |
| `52:7A02` | 遭遇步数，完整 16 位 | `37:1822` 先按有符号数与 1000 比较；小于时加一并回绕，再取原共享随机数 `%1000`，与递增后的计数做无符号比较 |
| `52:7A5C` | 遭遇允许标志，完整 16 位 | `37:1806..1808` 仅判断等于零；任何非零 word 均允许尝试 |

地图装载尾部 `29:F21E..F244`、重新开始 `46:D2B2..D2D4` 依据随机敌人表的第一个字节，按有符号 byte 判断大于零，写标志 1 或 0。C 在装载八字节随机表后按同一规则写入 `encounters_enabled`；运行时后来修改敌人表不会擅自重算该标志。

旧 C 只因存在可用敌人就尝试遇敌，因此独立写入标志 0 会被忽略。现在读取共享标志，计数器也绑定同一 World 状态，支持单字节／非对齐读写。新增四个绑定字节，总计 3520；写出这两处 word 的末尾进入未拥有地址时，整个 World 写入被拒绝。

原机会先成功执行机会判断、清步数、写模式 3／事件 0／上下文 0／初始化请求，再进入敌人编组服务。C 调整该顺序，敌人入口异常不会抹掉已完成的机会状态迁移。强行启用空表和所有非法敌人记录的完整入口行为仍待实现，当前保留迁移后返回诊断。

## 本次原版对照

12 条原公共前端行走路径，每条使用非空驻留敌人表，允许标志与列表独立设置：

| 路径 | 初始标志／步数 | 原结束结果 |
| --- | --- | --- |
| 禁用非空表 | 0／1000 | 仍模式 1，步数 1000，不消耗随机数 |
| 非零标志 | 1、2、256、65535／1000 | 模式 3，步数归零，无机会随机抽样 |
| 机会未中 | 1／0 | 仍模式 1，步数 1，消耗一次随机数 |
| 阈值最后一次抽样 | 1／999 | 模式 3，步数归零，消耗一次随机数 |
| 高于阈值 | 1／1001、32767 | 模式 3，步数归零，无机会随机抽样 |
| 有符号负值 | 1／32768、65534 | 仍执行递增与一次随机抽样，随后模式 3、步数归零 |
| word 回绕 | 1／65535 | 递增为 0，仍模式 1，消耗一次随机数 |
