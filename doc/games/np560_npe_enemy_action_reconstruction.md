更新：2026-10-06。依据本地原厂 `NP560.PRG` 反汇编与独立原厂运行时采样。
本文地址为 PRG 源地址；运行时分页调用地址需加 `0x1D` 才对应源银行。

## 撤销此前字段解释

旧文将角色 `+58`、敌人 `+29` 当作普通伤害下限参数，依据的字节 RAM
采样有误。这两个位置实际是各自的第一项仙术，不能继续用于伤害下限。

| 数据 | 原厂装载／更新 | 当前解释 |
| --- | --- | --- |
| 角色当前等级 | 初值来自角色 `+35`，战斗装载及升级写 `6468` | 角色下限为当前等级除 5 加 4 |
| 角色 `+58..+75` | 初始仙术表 | 首项仙术不参与伤害下限 |
| 敌人 `+14` | `31:CA80..CAEE` 写 `6468` | 敌人下限为此等级参数除 5 加 8 |
| 敌人 `+29..+31` | `31:CE7A..CF20` 写 `6469..646B` | 三项仙术编号 |

正确定位 `6xxx`／`7xxx` 页后，还需区分字访问与 DMCU 字节访问。
本次采样的字节访问在对应字地址之前一字节。隔离开场战实测角色等级 1、
仙术 `4/6/10`；敌人记录等级 9、仙术 `6/0/0`，与装载链相符。
证据脚本：`tmp/battle-native-floor-fields.mjs`，结果
`tmp/battle-native-speed-order-8.json`。

C 的旧命名 `damage_floor_stat` 暂保留存档布局兼容，但角色值由当前等级
推导，敌人值读取 `+14`。读取旧 C 存档时重新由存档等级推导角色值；
`NPESAV14` 布局不变。隔离测试把旧字段存为 99、等级存为 2，读回下限参数为 2。

角色普通攻击入口为 `2D:3644`，敌方为 `33:6DB0`，不能共用角色公式。

| 行为 | 源地址 | C 行为 |

| 敌方普通攻防差 | `33:7088..70A6` | 先加浮动再取倍率乘积低字；没有 999 上限 |

防御命令的四分之一减伤仅高于伤害下限时生效，可在防御者实际行动前生效；行动时另有基础防御加
100 的写入，两者不是同一规则。倒下而未执行的队员不取行动随机值。
逃跑失败会把全队指令改成普通攻击，实际行动者仍取两次准备随机数。
旧“仅执行敌方阶段”判断已撤销；敌方隔离规则探针改用执行前睡眠的防御者夹具。
最新原厂分支、行动顺序与 SDL 回归见[失败逃跑指令覆盖](np560_npe_failed_flee_commands.md)。

精确 RNG 测试包括：两名较快队员防御与一名无仙术敌人共 7 次抽取，
种子 1 的终态 `20D01480`；仅一名存活队员防御共 5 次，种子 2 的终态
`2A88C8FF`。目标初选倒下者后扫描不增加抽取。伤害测试覆盖敌方下限、
前后两次浮动、下限分支跳过减伤、防御乘法低字回绕与非正效果。此前 999 上限结论已撤销。普通正属性倍率仍按已确认的 1 处理；
异常倍率及全部效果尚未验收。最新 17 条原厂输入与 C／SDL 对照见[带符号战斗规则](np560_npe_battle_signed_values.md)。

## 已接入 C 的敌方仙术

`32:D474..E2AA` 的决策顺序：

1. 三项仙术全为零时不抽策略随机值，直接普通目标选择。
2. 有仙术时先抽 `%100`；通常阈值 90，脚本战的中间敌槽阈值 80。
   小于阈值则普通攻击。封印或第四状态为负也转普通攻击，但已取的策略随机值保留。
3. 再抽 `%100`，小于 50／75／其余选择技能槽 0／1／2。空槽向前扫描至槽 0，
   不重抽；槽 0 仍为空则普通攻击。
4. 按仙术记录 `+38` 选择敌方自身阵营或角色阵营，再抽一次目标，
   包括倒下槽及编组空槽；向后扫描并绕回至存活目标。

敌方不执行角色的等级和气门槛，也未在敌方计算入口找到扣气。
运行时 `22:23C4` 的仙术加载器实际是源 `3F:23C4`，旧源地址解释撤销。
敌方 `33:73DC` 加载该记录，读取 `+14` 效果类型、`+37` 群体标记与 `+38` 阵营标记。

- 类型 1：自身阵营的体力效果直接使用记录 `+15`；攻击角色阵营时减去
  **有符号目标防御除以施法敌人 `64A6` 的商**和有符号浮动，非正值回退为 12。
  `64A6` 来自敌人 `+23/+24`；`33:7522 DIV` 的被除数在 R7，不能误写为减去完整防御。
  敌方气／攻／防效果准备值被清零，不能套角色攻击增益。
  `36:1F18` 写效果缓冲，`2A:0000` 后续提交体力；自身治疗只作用于存活目标，
  按记录体力上限夹值，不复活倒下者。相加保留低 16 位，比较使用有符号值。
- 类型 2：`+31/+33/+29/+35` 按毒／眠／封／第四状态映射的四个有符号值加到目标状态，群体／单体
  分支来自记录标记。包括倒下记录，按 16 位相加，不加自行设计的免疫拒绝条件。
  C 已增加第四个战斗状态；角色第四状态为战斗临时字段，没有改 V14 存档布局。

### 状态计数与中毒

`33:C7E4` 在下一轮菜单准备时调用 `38:F78C`：六个状态字负值向零推进，
前四项正值免疫不递减（`38:FA6C` 的下标检查）。后两项是攻防计时字段，
正值递减、到零复原；现有 C 增益时长和防御计时仍有待逐行动对照，不能把
这次四项状态修正算作全部状态规则完成。C 在继续战斗的一轮末推进负值；
全队眠／封时连续执行空队员轮，直到可选命令或败战。

`39:605C` 调用的 `36:6FBC` 实际包含中毒结算，不能当作通用递减函数：

后续已按 `36:6FFE..708C` 全行动标志门槛修正 C：只在实际行动后调用，没有实际行动的轮次不扣毒伤。源 `38:FEA2..FEF2` 的脚本战中间槽眠 +10 刷新也已接入；详见[复活与状态门槛](np560_npe_revival_and_poison_gate.md)。

- 角色中毒先令共享局部伤害为敌槽 0 等级的两倍；该等级零时取槽 1。
- 随后如果存在存活的中毒敌人，同一个局部量被第一位队员等级的两倍覆写。
- 两侧所有存活中毒记录扣除**最后同一个伤害量**，体力夹零。这是源码行为，
  不改成各自按不同施毒者计算。中毒杀死最后一个敌人会走正常奖励与胜利后续。

`33:BBCC` 是战斗结束检查／显示链；`4D:E586` 是下一行动者选择，均不是状态递减入口。
状态入战清零、跨战斗持久性、双方同时毒倒的胜负优先级及逐帧表现仍待完整核对。
