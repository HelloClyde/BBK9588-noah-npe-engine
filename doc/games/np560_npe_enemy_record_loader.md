# 敌人记录装载与16位选择号

更新：2026-10-09。生产代码使用C11，文件读取直接来自当前NPE；QEMU及原前端仅提供参照。

## 实现

原公共装载入口源50:2882..28A8在选择敌人之后检查52:7A9A：值1调用CODE14:C76E（源31:C76E..D76C），其它值调用CODE15:8A72（源32:8A72..995E）。两条装载路径有以下区别，C现按实际入口实现：

| 行为 | 剧情路径 | 普通路径 |
| --- | --- | --- |
| 选择号零／负数 | 只清两项掉落、金币与经验奖励，其它记录保留 | 零号跳过全部读取及记录修改；非零号包括负数继续装载 |
| 攻击／防御字段读取 | 读当前值+96/+98，再复制到基础值+92/+94 | 读基础值+92/+94，再复制到当前值+96/+98 |
| 攻击组+44 | 保留读取的值 | 读取后清零 |
| 第二个物理敌人槽的眠状态 | 最后写10，即使是未使用槽 | 不写此免疫值 |

目录位置按`base + signed16((selection*4-4) mod65536)`计算；撤掉生产入口对文件敌人数及255的限制。正数16385回绕到敌人1，16386回绕到敌人2，16435回绕到敌人51。选择号按完整word处理，记录图像也读取完整word。

每个非跳过敌人按原顺序执行两次寻址、19次读取。姓名12字节、图像word、等级byte、HP／气／攻防／其它属性word、三次单字节仙术、两项掉落、金币／经验及攻击组逐项写入。等级和仙术使用不同局部字节；仙术三次读取共用自己的局部字节，后续敌人也沿用其短读剩余值。短读不清未读取的尾部；目录局部四字节在读取前保留绝对目录位置。最后清六个状态／计时word并设置原编组坐标。

生产普通遭遇、剧情战斗和追击入口已调用共同C服务，撤掉这些入口中整块清敌人属性的处理。实际装载后的名字、图像和未建模字段由148字节驻留记录保留。原记录byte12与宿主用于诊断的八位文件索引分开；九条敌人绘图路径改读记录+46的16位图像号。

## 文件寻址与公共入口证据

在原公共行走入战中，负数65535和32768访问敌人目录前面的字节，所得载荷偏移超过文件长度。寻址失败后继续从旧文件游标读取，不能把游标直接设为越界位置并把所有读取当EOF。C敌人装载的文件适配器现保留旧游标；其它资源适配器的全部失败语义仍待核对。

四条新原前端路径：回绕敌人1、回绕双敌、回绕敌人51、两项负选择号与中间有效敌人。共32张原画面，与直接C／实际SDL及实际main SDL各32次比较零差异；每路还比较已用七个敌人槽的完整148字节记录，共1036字节。初始敌人目录指针也与原前端及当前NPE头一致。NPE文件未修改。

负号路径初版HP为零、普通路径攻击组保留为3的失败记录保留；修正旧游标保留和普通路径清攻击组之后，属性、全部记录及画面一致。该证据覆盖这些入口，不证明全部异常编号的后续操作或完整文件系统。

## 原函数与C服务验证

`reference_enemy_record_service.py`执行未修改的两条原装载函数和原乘法函数。文件寻址／读取是明确适配边界：按当前NPE供给数据，可诊断限制某次短读；越界寻址保留旧游标的规则由上述公共路径另验。

23组参照与C服务的完整128KiB RAM、读取目标／数量及寻址请求一致，包含队伍前缀0～3、剧情非正选择、普通零／负选择、256／8193／16385／32767、目录0～3字节短读、文件尾、姓名短读及跨敌人的局部字节保留。16组无额外短读限制的用例再经生产RAM运行时和真实NPE读取，完整128KiB结果一致。数量0仅验证原装载函数，没有宣称实际完整入战通过。

原固定供给诊断最初使用错误的长立即数比较及意外读取保护，失败日志保留，最终23组均正常返回、栈恢复且无ROM缺失／未支持指令。数量255的早期固定供给失败不作为原行为结论；需要动态IO与更大地址范围的后续验证，仍未完成。

构建17个相关目标无警告，16项必要短检查退出0。旧选择32组、自身NPESAV22存读及选择保留、普通行走入战84帧、旧编组选择入战32帧、剧情20帧、队伍映射16帧、剧情回退52帧、剧情驻留入口28帧、六条胜负后继、胜利68帧、升级战后159帧、失败26帧和追击保持。资源回归58条完整RAM路径保持：该原夹具显式零初始化且仅设置资源目录，C测试先断言新增敌人目录等于NPE头，再还原该四字节初态；未修改旧原RAM参照。
