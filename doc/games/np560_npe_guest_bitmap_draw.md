# 客机内存位图绘制（2026-10-08）

纯C入口`npe_draw_guest_bitmap`通过客机RAM读回调取得位图，修改调用者保留的240×120索引缓冲。生产代码在`npe-sdl/guest_bitmap_draw.inc`，经`npe.c`链接到SDL主程序；实际world／main资源装载与绘图调用尚未切换到此入口。

## 原代码及移植规则

PRG物理20:42C0／42C4／42C8向量分别指向运行时0D:7C34／7ECE／8232，即物理2A段三函数。源码摘录保存于`tmp/guest-bitmap-draw-source.asm`，生成工具为`tmp/dump_guest_bitmap_draw_source.py`。

- 先读取10字节头，不检查位图签名。宽、高只取字节6、8，高字节被丢弃；每行源跨度为`((width+3)/4)*2`。
- x、y按无符号16位与240、120比较；负起点完全不画，右侧、底部裁剪。零宽／零高保持原缓冲。
- 偶数起点：0覆盖、1只填目标为0的像素、2跳过源0。0的奇数起点也按源像素覆盖。
- 1的奇数起点只在首行执行填背景逻辑：原81FE直接跳到2的845A行循环。后续行按2继续，无重新初始化。
- 1的奇数起点在原816E／8180路径使用R1保留的低字节；移植保留整个16位R1的移位状态，不用通用像素规则替代。
- 2的奇数起点在原84D4使用当前源DS段内00F0的RAM字节作掩码；84F8存储RB7而非组合后的RB10，偶数宽末尾会把邻接低半字节写0。这些原行为已保留。

原缓冲按行倒序保存，两个像素一字节；C接口输出正向索引图，探针同时重建原14400字节排列作整缓冲对照。客机字在偶地址高字节在前，位图头本身的低字节尺寸规则独立于此。

## 独立原函数核对

`npe-sdl/tests/reference_guest_bitmap_draw.py`使用原QEMU执行未改动的三函数，检查CODE总线字节与原PRG一致。明确种入显示缓冲、源位图与少量RAM掩码；没有绘图桩。绘图指针通过ES=0的逻辑84FC／84FE写入物理0004FC／0004FE，不能误用IGNDS内部84FC窗口。

35组均正常返回、栈恢复且无缺失ROM／不支持指令。覆盖奇偶起点、三种模式、1像素宽、255宽右下裁剪、负数／出屏、零宽／零高、奇数起点偶数宽、R1保留字节及0F／F0银行RAM掩码。源地址含奇地址及8000边界，头签名与尺寸高字节故意非标准。

`guest-bitmap-draw-probe`比较每例全部28800个索引及14400个打包字节，共1008000＋504000字节一致。探针还检查绘制未改动源RAM；断言在发布构建仍启用。此前通用实现在`odd-kind1`的(4,4)得到10而原函数为5，此差异由81FE跳入2的循环引起，已按原源码修正。首次采样错误使用内部84FC的失败日志`tmp/guest-bitmap-draw-native-first.log`保持。

结果：`tmp/guest-bitmap-draw-native/report.json`、`tmp/guest-bitmap-draw-report.json`。7组资源分配／读取／清理、13组装载与内存绑定短回归通过；四目标构建无警告，五项原资源哈希保持，自身存档仍为NPESAV22。
