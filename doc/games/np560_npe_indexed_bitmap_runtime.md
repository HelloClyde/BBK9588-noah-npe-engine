# 通用索引位图服务与生产管线

2026-10-08。实现为纯 C；Python／QEMU 只用于独立原函数对照，生产程序不依赖它们。保留自身 NPESAV22，原机存档互通、正常属性完整通关和 SDL 全程实玩继续排除在验收范围外。

## 原函数规则

原 PRG 物理 `48:0000..0246`，运行时 CODE `2B:0000..0246`。它与战斗驻留位图装载服务不同：

- 参数是零起始的有符号16位索引、X、Y及绘制模式。索引负数、模式不在0～2或超过目录长度返回 `-1`。
- 目录边界使用 `sign16(low16(index*8+8))` 与 `52:79C6` 的有符号32位长度比较；文件定位独立使用 `sign16(low16(index*8)) + long(52:79CA)`，保留两处回绕。
- 分别读取4字节相对偏移和4字节长度，两份局部缓冲先清零。偏移为负或长度为零返回 `-3`，不分配。
- 分配请求为 `low16(length+1)`，解析包括失败句柄0；载荷定位为 `long(52:79CE)+relative`，读取长度取低16位。短读只覆盖实际读到的字节。
- 按模式0／1／2调用原三种客机位图绘制。随后解锁、释放捕获在局部帧的句柄，返回0；不会像战斗服务那样重新读取全局句柄槽。

原 `31:EBD6..EC26` 将段表中的目录偏移、目录长度及载荷偏移分别读入 `79CA`、`79C6`、`79CE`。C运行时新增目录长度初始化，取当前 NPE 第0段大小。

原地图图块调用 `4A:9108..914C` 使用模式0；人物调用 `46:BD80..BDD6`／`46:BE2A..BE76` 使用模式2。调用者忽略服务的原错误返回。C保留这一规则，但客机地址超出已实现RAM范围的适配错误仍向上传递。

可复现反汇编：`npe-sdl/tests/dump_indexed_bitmap_source.py`，输出 `tmp/indexed-bitmap-source.asm`。

## 生产接入

- `indexed_bitmap_service.inc` 实现原通用服务；`rpg_runtime.inc` 提供当前 NPE、客机RAM、真实堆、文件游标和绘图适配。
- `npe_render_map`、增量NPC底图恢复、人物／NPC／追击对象绘图，以及敌人图像的通用绘制 helper 接入该服务。敌人移动的填背景分支使用模式1。
- 位图元数据增加来源索引与来源类型。驻留战斗图组和动画组不冒充全局索引图；没有运行时的离线资源检查仍使用文件视图。
- 场景中的实际装载、临时分配、绘图、解锁和释放均发生在文件拥有的RAM运行时中。
