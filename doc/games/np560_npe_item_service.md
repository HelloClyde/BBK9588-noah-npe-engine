## 原服务与实现

原模式 12 为运行地址 `27:5A68`，PRG 源 `44:5A68..5DB6`。先设置地图初始化标志 7AB4，再取事件号低字节；仅 1～5 有效，非法号写模式 0。读取 `52:76B0` 五槽驻留表，步长 8：数量、道具索引、后续编号各一字，增加标志和后续模式各一字节。

源 `29:ED26..EE8A` 从 NPE 地图第 13 组读取前项，最多五项；未提供的槽保持。`NpeWorld.item_events[5]` 采用相同生命周期，地图装载、暖读档和暖新游戏只覆盖提供记录，`raw` 指针清零。缓存不写入 NPESAV17。

- 数量运算保留 16 位回绕。增加不设上限；扣除先回绕，再按有符号结果判断，负值清零。增加标志任意非零都表示增加。
- 原索引 0 也参与库存运算；其名称装载清空名称，显示空引号。已撤掉 C 对索引 0 的拒绝。
- 名称装载用索引低字节，库存寻址用完整有符号字。这批 C 实现覆盖库存索引 0～254；负索引或大索引对其它 RAM 字段的别名访问仍未实现。
- 原固件 `4C:A998/A99E/A9B6` 提供“失去\"”“得到\"”及结尾引号。提示如 `得到"金创药"`，**不显示数量**，名称从 NPE 读取。
- 原 `03:4050` 接收名义 2000ms，可按键结束。实际 `main.c` 保留底图、显示提示、等待、恢复底图后才执行后续；返回地图时消耗初始化标志并重新装载地图。

`world.c` 分离查槽、数量变化和后续派发，`main.c` 的 `show_item_event()` 执行可见流程。主机关闭返回 -2，此时数量已改变，后续仍待执行。

另两条使用原 NPE 地图 1 的第 1／5 槽记录，分别是道具 150／146、增加 1、后续模式 1／编号 1；库存初值仍是明确的诊断输入，未修改这两条原记录。

共 22 条短流程、60 次原 LCD 提交，与实际 `main.c` 调度产生的完整 240×120 C 画面及实际 SDL 渲染读回逐像素一致。库存终值、模式、事件、初始化标志和 RNG 保持通过；原名称字节另与 NPE 解码逐项比较。

参考运行时每批提交的 RAM 是批次结束状态，不能视为每次显示瞬间的 RAM。提示期间尚未派发后续的顺序由原源码及 C 提交断言支撑；不宣称逐指令时序对齐。
