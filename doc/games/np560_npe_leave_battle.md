- 七组分别8／6／6／4／8／6／8次原 LCD 提交，合计46次。离队提示及恢复之后直接进入四段战斗首屏，未增加中间地图提交。
- `sdl-leave-battle-probe` 调用实际 `main.c` 的 `advance_world_events` 和 `draw_battle_entry`，使用未修改的当前 NPE 及当前地图队伍缓存。46次 C 索引图和实际 SDL 整屏均零差异。
- 每次提交核对模式／事件／上下文、视口及主角方向、NPC位置／方向、菜单人数缓存和126个已建模角色字段。入战还核对人数、行动角色、目标、三槽敌人和每个紧凑战斗记录的体／气、攻防、速度及四状态。
- 离队服务仍以活动标志恰为1判断；战斗人数从三槽裁去尾部零标志。因此 `[1,2,1]` 离队后为 `[1,2,0]`，原战斗人数为2。这两个服务的判断条件不能合并。

## 撤回此前提示按键结论

原定时等待链 `20:4050 → 4F:D530 → 4E:F282` 先检测 `4F:4C34` 的提前返回条件，再接受 `type=4,code=0xF0` 的计时消息。此前文档只考虑了计时消息，声称普通按键不会提前结束，证据不充分，撤回该结论。

`--timing-only` 在提示显示后第20次 `advance` 注入七种输入掩码，方向、确认、取消和F4全部使原参考在该次返回提示并入战；无输入时恢复在第133次。`--timing-steps` 补采0／16／64并记录原提交指令偏移：提示至恢复分别12922272／2922763／2922875步。参考接口报告 `stepsPerSecond=0`，因此不能换算为精确墙钟时间。单次 `advance` 可有多个提交，不能以调用次数替代原硬件时间。

上轮 C 的离队和存档失败提示仍忽略普通按键，等待名义2000ms；受控无输入时钟及回绕检查通过。**上轮该差异尚未解决（现已由定时提示修订解决）**，当时需解释 `4F:4C34` 的系统／键盘状态条件及参考运行时调度，才能决定其完整 C 输入规则。本轮没有凭采样推测改动生产规则，也不宣称输入等待服务完全复刻。

相关文件：`tmp/native-leave-notice-input.json`、`tmp/native-leave-notice-steps.json` 和对应日志。系统存档失败使用同一服务，此前“按键忽略已复刻”的结论同样撤回；当前共享等待改为按键结束。
