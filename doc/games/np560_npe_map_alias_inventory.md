# 地图群体状态写入背包后的异常列表

更新于 2026-10-06。纯 C11 + SDL2 已接入本页核对的地图使用流程。
物品字段、名称、图像与异常读取结果均来自当前 NPE；没有针对 212／214 写固定结果。

## 原厂实际扫描与读取

地图群体类型 2 既有服务将效果重复四次写入背包 212～214 的别名字。
本轮独立三人夹具使用状态效果 `7/-5/11/-13` 后，库存得到 `28/65516/44`，队员状态不变。
原厂列表扫描 1～254 的有符号正数量，所以显示 212、214，排除负数量的 213。
扫描源 `4D:1FBE..208E` 没有检查实际物品记录总数。

原厂通用物品装载 `3F:C370..C846`：

1. 定位到物品段起点加 `(ID-1)*4`，读取四字节偏移。
2. 将物品段起点与偏移按两字加法相加，低 32 位回绕。
3. 尝试定位到结果位置；定位失败时文件位置仍在刚读的偏移字后面。
4. 调用者忽略定位返回值，继续读取名字、固定效果字段及说明。

本轮运行验证了原文件的大偏移失败、正值越界失败、有效记录重定向及偏移回绕。
`npe_native_item` 实现该装载；原 `npe_battle_item` 转调同一服务。
资源检查接口 `npe_item` 仍验证记录目录，异常运行路径不再依赖这个检查接口。
读取仍验证宿主文件边界，残缺读导致的原厂缓存残留尚未完整实现。

《天降风云 V1.3》只有 175 件物品。本轮原文件采样如下：

| ID | 目录位置读出的偏移 | 原厂实际字段起点 | 类型／群体／阵营 |
| --- | --- | --- | --- |
| 212 | B5C4D1A5 | 物品段起点 + 212×4 | 211／178／187 |
| 214 | D6CABCE1 | 物品段起点 + 214×4 | 203／249／43 |

两个偏移字来自正常物品说明的 GBK 字节。定位失败后后续说明被读成名称及效果，
因此列表出现原文片段，并按实际大于等于 25 的类型显示“该道具只能装备!”。
确认不会消耗这两项数量；拒绝等待两秒，期间的 F4 被忽略。

## 图像、文字与局部重绘

原厂图像查找以物品图像起点加 `ID-1`，不要求结果仍是正常道具图像。
在本文件中，212 得到 50×60 的角色图，214 得到 87×29 的金钱图。
C 版读取这些原图并按 LCD 边界裁剪。

- 数量用固定 6×12 单元的不透明白底绘制，包含字形间隔与底部两行；
  长异常名称与数量重叠时按原厂擦除，数量本身只取前两个十进制字符。
- 列表 ASCII 字距为六像素，中文十二像素；已用文件头 `NP560 RPG2.1` 的回绕夹具核对。
- 详情更新只清图像区 `x10..42/y72..104`，新图仍按自身宽高绘制。
  上一张超大图的区域外像素会留下；切到较小金钱图时保留原厂角色图底部。
  描述区域在图像之后清为白底 `x45..230/y72..110`，覆盖超大图的相应部分。
- `npe_update_item_list_screen` 与 `NpeItemListView` 保存地图使用列表的先前像素。
  群体执行或单体目标页 F4 后重新进入扫描，清屏并回第一项；拒绝后继续局部更新。
- 单体目标页按原厂固定两字符数量与十二字节名称字段擦除背景，
  保留超大图在字段外的部分；目标页 F4 重扫后选中第一项。

以上局部更新目前接在地图“使用”路径。装备／战斗的异常图像导航与拒绝后残留
尚未新增独立原厂验收，不能由正常装备／战斗回归推断已完整复刻。
