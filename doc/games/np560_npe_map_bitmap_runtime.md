# 地图／人物资源图组驻留读取

日期：2026-10-08。纯 C 运行时补齐原 NPE 图组 0～4 的驻留初始化；生产 NPC、人物、追击对象和敌人绘图改由已有索引调用链读取这些实时字。

## 实现与原指令

`rpg_runtime.inc` 使用统一的九项地址表，按当前 NPE 头顺序初始化图组 0～8。`npe_image_group_index` 在已绑定运行时读取相应 RAM 字，按 16 位相加；未绑定的查看接口仍读取当前文件头。

| NPE 图组 | 驻留字 | 用途 |
| --- | --- | --- |
| 0 | 52:7AFC | 原初始化状态／图组查询接口 |
| 1 | 52:7AE6 | NPC、固定地图怪物 |
| 2 | 52:7AEE | 追击对象 |
| 3 | 52:7AFE | 地图人物 |
| 4 | 52:7AF2 | 敌人通用图片 |
| 5 | 52:7AE4 | 道具图片 |
| 6 | 52:7AF8 | 肖像及战后提示 |
| 7 | 52:7AEC | UI 图片 |
| 8 | 52:7AEA | 仙术图标 |

原物理 `31:E956..EAAC` 顺序读入这些头字段。NPC `4B:25C8`、人物 `46:BD76`／`46:BE16`、追击 `3A:5E6A` 和敌人函数读取各自驻留基址。初始化及各调用留存在 `tmp/map-group-source.asm`。

**地图块保持原始图号。** 原物理 `4A:912E..9148` 从 `52:70B4` 视口缓存读取字后直接压栈调用 `2B:0000`，没有加 `7AFC`。C 的地图和恢复底图调用保持这一行为；图组 0 的初始化／查询证据不作为“地图块应加基址”的依据。

没有改变运行时所有权、记录绑定、堆／IO 服务、字体或 NPESAV22 格式。旧缓存计数和头投影不能覆盖已绑定的驻留图组值。

## 独立原函数参考

新增 `reference_map_bitmap_runtime.py` 输出全新目录 `tmp/map-bitmap-runtime-native/`，没有覆盖以前的参考。原分配前缀、装载、浮点／动画及绘图代码保持；参考仅在文件 IO、分配提示及显示等待边界适配，并诊断初始化九个图组字。本参考不是完整原启动或原 UI 调用者 RAM 的验收。

138 组参考包含以前 108 组和 30 组新增案例。新增对图组 0～4 分别检查当前基址、基址加一、65535 回绕、32767 加一形成负索引、目录外基址，以及移到 40×50 敌人图片。图组 0 案例验证驻留状态／查询接口与孤立服务，不替代原地图调用者语义。

`map-bitmap-runtime-probe` 在无 World 和绑定实际 World 两种上下文中执行，合计 60 条路径；每条比较完整 128 KiB RAM、28800 个索引像素、游标／读取／失败记录及真实 SDL 输出。修改宿主头缓存后仍读取运行时字。全部一致。

五类公共夹具生成器迁到新 138 组参考；通用资源排除新增图组案例后仍有原 29 组，UI 22、库存 24、场景 13、角色动画 20。原有参考文件和旧轮报告保持。

`tmp/map-bitmap-initialization-diff.json` 比较旧 108 组及其 219 个动画帧：画面、打包 LCD、IO 记录和坐标完全不变；完整 RAM 只有四个新非零驻留字共八字节改变。第 0 组在当前 NPE 为零，所以初始化后没有额外差异。

## 原公共输入／实际主程序

`reference_map_group.mjs` 恢复原第一张地图快照，仅在已有诊断 NPC／人物设置外改写 NPC 驻留基址，再等待原公共定时事件。六例基址为 1138、1139、65535、32767、2000 和 1393，分别产生正常、相邻 NPC 图片、地图块、负索引、目录外索引和敌人图片。

`sdl-map-group-probe` 的六份完整 C 输出、六次直接 SDL 比对和十二次实际主程序 SDL 比对均与原参考一致。绑定后将宿主缓存图片总数改为 1、修改头图组 1，仍正确显示驻留值。实际主程序每例比较定时提交及忽略 F12 后的缓存重显；没有把重显算作独立原全地图重画证明。

新公共参考为六张输入及六张输出。静止 NPC 的图号／方向／坐标及模式保持；其它图组的变化依靠原服务参考、调用者指令及既有健康路径验证，未宣称所有异常组合或完整调用者 RAM 已通过。
