# 原type1物件清除与正常标题读档（2026-10-09）

## 本批范围

纯C移植原CPU25:3082的type1分支（PRG源42:30A8..3286），接入实际地图装载及当前地图拾取。参考由未修改原函数执行生成，不使用C输出反向修改原参考。补齐正常启动到标题再读档的人物分区证据；仍使用模拟器自身NPESAV22三槽。

## 清除服务的原顺序

- 参数按16位有符号数解释。负值执行批量清除：标志0..99外层递增，每个标志恰好为1才检查全部8条物件记录；ID减1按16位回绕后比较。遇到零ID仍继续其它记录。
- 非负值直接访问指定物理记录，不限制到8槽，也不先检查ID或标志。本批指定槽样本为0、8、255，未证明全部非负槽与全部地址空间。
- 每次清除按原顺序重新读取Y、地图宽度字节、X，再按乘积与相加的低word计算有符号格索引，重新读取地图指针，写入word53。前次写入与标志、指针、坐标、宽度或ID重叠时，后续读取使用已改变的值。
- 原奇地址MOV在物理RAM中先写低字节；诊断RAM图片以大端word排列，所对应的图片字节位置为地址减1和地址加2。C在本服务中处理此转换；没有把所有RAM服务都宣称为奇地址等价。
- type1本身不额外刷新105格缓存。实际绘制与地图装载使用原有缓存后继。

实现位于`npe-sdl/map_object_clear.inc`、`npe-sdl/rpg_runtime.inc`及`npe-sdl/world.c`。拾取先写标志，再读取实时坐标并调用指定槽清除；自身保存的稀疏地形表只记录结果。实际文件所有者和当前地图均匹配时走该运行时分支，诊断World与已加载地图不同时沿用独立World路径。
