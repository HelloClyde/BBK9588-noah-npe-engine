# NPE地图缓冲与实际绘制链

## 原网格服务

原CPU0C:BF0C..BFB4（PRG文件9BF0C..9BFB4，物理29:BF0C），0xA8字节原循环保持未修改；诊断沿用原LINK／保存寄存器前缀，替换结束返回和文件字节适配。每例执行区间逐字节核对。宽52:7A56／高52:7A5A是byte，乘积只比较有符号低word；负乘积不读取网格。每项先按实时52:797E指针加索引*2清word零，然后重读指针读取2字节。写入改变指针或宽／高会影响本次读取或下一次循环；短读／EOF保留清零后的未覆盖字节。

纯C服务为`map_grid_stream.inc`。`reference_map_tile_records.py --grid`使用独立`tmp/map-grid-native`输出，未覆盖旧21组原地形参考。13组包含空、1／4／105格、负乘积、清零改指针、读入改宽／高、最后1字节和EOF、真实138／139／140。`map_tile_records_probe`核对完整128KiB RAM和每次文件目的地址／数量／游标；三组真实地图另经生产运行时核对。

## 主流程接入

`npe_rpg_runtime_map_load`读取实际NPE网格、清除已拾取的前100号物件地形、执行原地形装载并刷新105格缓存。World资源打开、换图、构造完成和重开调用该入口；构造期间地图号尚未赋值时不提前运行。部分Map视图属于前状态副本或离线资源预览，只有当前运行时World所有者接入驻留绘制；此限制防止副本误读另一个实时状态。

`npe_render_map`在当前World运行时绘制固定105项，使用原缓存的有符号／回绕索引；普通离线资源视图仍使用文件网格。`npe_world_tile`读取当前地图缓冲；拾取和剧情更新同步实际word，周期完成标志byte同步至槽+62。周期负索引按原42:335C..335E的SLE停止，新增短检查保留零终止和负终止的区别；完整周期服务及驻留元数据联动仍未移植。

自身NPESAV22读档按已验证的覆盖次序回放地形，恢复三个已应用标志，再刷新缓存；暖恢复和CLI继续游戏均接通。此阶段服务模拟器自身格式，原机存档互通保持排除。新增`map_runtime_chain_probe`验证地图108门格196→10、实际缓冲／标志、保存后破坏RAM再暖恢复、重开切换地图、冷读档恢复和绘制；NPE指纹保持。
