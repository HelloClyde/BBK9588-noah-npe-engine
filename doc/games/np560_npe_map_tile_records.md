# NPE地形记录原地址装载

## 原证据与C实现

来源为当前`tmp/NP560.PRG`的文件0x9D238..0x9D584，CPU0C:D238..D584（原反汇编显示29:D238）。诊断只替换文件读取适配及片段结束返回，执行区间逐字节校验不变。三个64字节槽从52:724E开始：阈值+0，索引+2，地形+32，标志byte+62，padding+63。内层数量是调用者局部byte，不是槽中字段。

原装载遍历三个槽；存在槽读取完整byte数量，允许16／31／255项覆盖相邻字段；每对先读索引、再读地形，随后读取实时进度与阈值，达到阈值时按有符号16位索引乘2加实时地图指针写word。零索引也会装载，不能套用周期更新的终止条件。存在槽只清标志byte，未填字段保留；缺槽只清阈值与15对word，保留标志及padding。

实现：`npe-sdl/map_tile_records.inc`的`npe_map_tile_record_service`。`npe_rpg_runtime_map_tile_records`从当前NPE的地图尾部读取，使用实际运行时RAM／游标及当前地图指针。`npe_map_tile_changes`仍是最多15项的类型视图，但去掉不符合原版的网格范围和符号拒绝；该视图尚未替换为完整驻留表，超长记录主循环适配仍未完成。

## 验证

`reference_map_tile_records.py`取得21组原结果，`map_tile_records_probe.c`对照完整128KiB RAM及每次读取数量／游标／驻留目的地址。局部byte目的地是原栈地址，C以局部变量读取，比较数量与游标。覆盖缺槽／空槽、1／15／16／31／255对、阈值上下／相等／零、FFFF／8000／7FFF／零索引、2／3／4／255声明槽、跨槽和阈值／进度／指针别名。

两组真实天明V1.3地图140资源，分别进度1／1280，同时经生产运行时入口得到相同完整RAM。诊断原文件为只读输入；没有按游戏名修改资源或生产行为。

9目标构建无警告；5项短检查为地图基础、SDL地形变化、视口、出口、农夫路线。138／139保持完整装载与绘制；140的456字节事件记录及World初始化通过，绘制仍明确返回-1。18份NPE共1379张地图局部资源扫描退出0，不代表完整游玩已通过。

首次采样标记的IGNDS放在MOV前，未阻塞初始快照；修正为紧邻store，失败ROM／调用者保存在`tmp/map-tile-initial-marker-failure`。旧地图测试假设网格外索引应拒绝，与原证据冲突；改为核对4／FFFF读取值，保留短数据拒绝，旧失败日志为`tmp/map-tile-old-grid-assertion.log`。
