# NPE周期地形更新

## 原函数与C实现

原CPU25:3082的type2分支为PRG42:328A..346E；完整0x400字节函数与实际缓存函数CPU2F:E15A的0x126字节均未修改。诊断包装器只提供参数、栈和结束标记，进入原函数前核对执行区逐字节一致。参考同时检查寄存器标记、栈恢复及无缺ROM／非法控制诊断。

`npe-sdl/map_tile_update.inc`固定遍历52:724E起的三个64字节驻留槽。每槽只在开始读取一次阈值／实时进度52:7A66；零阈值、进度未达阈值、任意非零完成标志都跳过。最多读取15对，索引按有符号word小于等于零停止。每对重读实时地图指针52:797E及记录内容；最后写完成byte，保留相邻padding，再调用实际105-word缓存算法。该缓存刷新发生在每个生效槽后。

原函数保存调用者R0。C返回的生效槽数量属于宿主接口，不宣称与原返回寄存器相同。

## 主流程

当前运行时World的`npe_world_update_tiles`调用驻留服务；离线视图保留既有资源投影路径。宿主观察器只记录自身存档需要的地形覆盖，不重复写客体RAM。已应用位从实际槽标志重建，保存格式仍为NPESAV22。

52:7A66完整word双向绑定到World剧情进度。整word、单byte写入及越界事务保持检查通过；实际World绑定字节数从3554增至3556。剧情赋值能立即被原服务看到，地形地址重叠写入进度也会反映到World。

## 对照与主流程检查

原始诊断RAM共23组：空槽、零阈值、未达／恰达／FFFF进度、标志1／2／255、零及负索引、途中终止、15对、三槽、7FFF索引，以及写地形改变进度、阈值、下槽、后继索引／图块、标志和地图指针。完整128KiB RAM与纯C及仅绑定实时进度的World派发一致，文件游标／读取次数保持。

另用实际构造的World保留全部3556个绑定字节，只填充未绑定RAM和进度，再把确切初始RAM交原函数执行。相同23组完整RAM与纯C及全部World绑定的主派发一致。探针首先检查双方初始RAM一致；此组没有导入任意相互矛盾的角色副本，也不证明任意RAM快照可完整恢复。

24个目标构建通过；最终探针重建无警告。22项相关短检查通过，包含门格196→10、实际完成标志、暖／冷自身读档、重开绘制、SDL地形、94次原视口提交、出口和农夫路线、实际存读档／暖新游戏及14项受绑定数量变化影响的加载／声音检查。没有执行用户排除的全程人工验收。

## 保留的失败及剩余范围

首次启用全量绑定并导入任意RAM，23组都在更新前的导入比较失败；先前角色模型共享地图／战斗字段，不能保持两个独立副本。导出一次该模型再导入仍有23组初始差异，角色分类／视图变化也会影响记录。失败输出和两类原参考分别保留，原始任意RAM参考没有按C修改。

此问题归属完整共享RAM／角色记录模块，尚未修复。构造World组验证实际可构造状态中的周期服务，没有替代任意快照恢复。全部地形元数据写入者、动态记录的自身存档恢复及异常地址空间仍需接通；World构造超过15对的类型投影、53项稀疏覆盖限制仍存在。原完整调用者RAM／栈、LCD／IO及物理时序没有在本批证明。

整体仍粗估80%，引擎未完成。原机存档互通、正常属性完整通关及SDL全程手动实玩保持排除。
