# 金钱与道具事件的驻留共享

## 实现范围

两张地图事件表及金币值由同一份状态维护，文件装载、事件服务与资源运行时地址读写均访问这份状态。

| 原地址 | 布局 | 说明 |
| --- | --- | --- |
| `52:76B0..76D7` | 5×8字节 | 道具数量word、完整物品号word、后继事件word、增减byte、后继模式byte |
| `52:76DA..7701` | 5×8字节 | 金额word、后继事件word、增减byte、后继模式byte、保留byte6/7 |
| `52:799E..79A1` | 4字节 | 金币值，大端32位，直接共享`World.money` |

`76D8..76D9`两字节未认定为这两张表的字段，仍由资源运行时原始RAM保管。World接口拒绝超出所属连续区域的整次访问；资源运行时可逐字节跨过该空隙。新增84字节后，逐地址计数为3350个World绑定字节。

原装载器的源地址为`29:EBDC..ED22`（金钱）、`29:ED26..EE8A`（道具），对应运行时段`0C`。装载只覆盖当前地图声明的槽，未声明槽保留；金钱每槽最后两个字节也保留。冷初始化为零，暖读档和重新开始先保留缓存及填充，再按同一规则装载。

## 道具号与访问顺序

原模式12源地址`44:5A68..5DB2`，运行时段`27`。事件号取低字节1～5，物品名称装载也取低字节，但库存地址按完整有符号16位物品号计算：

```text
52:67C8 + sign_extend(item_word) * 2
```

因此高物品号能访问人物、出口、道具事件表、物品缓存或资源运行时原始RAM。实现撤销过去`item_index>=255`的拒绝；先尝试World所属记录，再在资源运行时确实绑定当前World时访问其RAM。不可访问地址返回诊断`-2`，尚未证明与原故障投递相同。

原先C提示先绘字再修改数量，且结束时沿用入口复制的后继值。现在按原指令：装载名称→修改库存地址→读取实时缓存名称→提示／恢复→重新读取入口同一槽的后继模式与事件号。入口槽号保存在局部变量，不因运行中共享事件号的变化而选错槽。无SDL的道具服务也按同一装载及续接顺序处理。

复现的错误是物品号1910访问自身第一个槽的后继word：初值5加2后原事件号变为7，C此前仍续接5。`tmp/item-resident-public-before-fix.log`记录了原画面一致但后继状态断言失败，修正后同一路径通过。

## 验证证据

- 原前端执行未修改的PRG／同一NPE，经系统读档、标题读档、新游戏和空槽入口得到16组完整装载结果；地图1、2、9、18、91、37、120，共1280字节与C一致，含全部金钱保留字节。
- 16条新原模式12路径，48次原LCD提交与生产分发器C缓冲及SDL读取逐像素一致；每条结束80字节事件表、目标word、模式／事件号、物品名称缓存一致。另验16次无SDL服务的数量／后继及表状态。
- 新路径覆盖普通增减、高字节事件号、物品256的人物记录、512的出口记录、65280的有符号负索引、1908的自身数量、1910的自身后继、1536的零号名称清缓存顺序、2560的原始RAM地址；含回绕、负值清零。
- 旧22条道具路径60次、18条金钱路径48次C／SDL提交保持；改为经共享RAM注入事件，金钱额外核对实时四字节值。两组旧缓存装载各8条保持。
- 部分字号、非对齐／跨槽、两张表的末槽及低字节事件索引、金币字节改写、World边界拒绝、暖恢复／重新开始与自身`NPESAV22`缓存不进线格式的检查通过。

原参考入口：`npe-sdl/tests/reference_money_item_resident_load.mjs`、`reference_item_resident_public.mjs`；夹具生成器和短检查与之同目录。当前构建、回归、源代码／原文件／字库及LCD哈希汇总见`tmp/money-item-resident-report.json`。
