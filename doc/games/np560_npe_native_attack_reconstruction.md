# NPE 普通攻击伤害：原厂代码到 C 的对应

更新：2026-10-06。此前把角色 `+58`／敌人 `+29` 当作下限字段的解释
已撤销；正确装载链与字节 RAM 采样见[敌方行动修正](np560_npe_enemy_action_reconstruction.md)。

普通攻击动作现已接入纯 C／SDL，七组单次／多人序列的 132 次原厂画面提交通过；具体姿态、动作间刷新与未验收范围见[普通攻击动画记录](np560_npe_battle_normal_animation.md)。本页保留伤害算术的重建记录。

原始固件 `NP560.PRG` 的 DMCU 源段 `2D:381C..385C` 读取当前行动者
战斗记录 `52:64CF + 0x94 * (52:7ACC - 1)` 的动作类型字节，以 0..6
索引七项跳转表。表的第 0 项是 `2D:385E`，普通攻击从这里进入。

2026-10-06 补查：表位于 `2D:3850`，类型 4 同样跳到 `385E`。
“围攻”由源 `42:8BBA`／`44:8B94` 设置为类型 4，并重选第一名存活敌人，
不是旧文档归于返回处理 `36:DE84` 的类型 0。详见[战斗菜单调用链](np560_npe_sdl_battle_menu.md)。

`2D:3888..38A6` 从 `52:64B0 + 0x94 * (行动者-1)` 读取当前攻击，
写入待结算伤害 `52:7926`。`2D:38DC..3952` 从目标记录的
`52:64B2` 读取当前防御，计算攻防差及倍率乘积并取低字，再作为带符号数限幅。目标索引来自行动者记录
`+0x7E` 的一基目标号。原厂还在 `2D:36A6` 提前取一次随机数对 6
求余，形成 -3..+2 的浮动。

`2D:39A6..3A28` 读取行动者记录 `+0x18` 的字节，以整数除以 5
再加 4 作为伤害下限；`2D:3A2C..3A46` 将上限设为 996；
`2D:3A4A..3A54` 最后加浮动。负数会在后续结算路径处理，当前 C
函数将其夹到 0。原厂 `2D:37A4..37C2` 在伤害前计算战斗记录
`+0x5A` 属性相关倍率：对双方该属性均为正的普通情形，先以行动者
属性除以双方属性之和，
整数商为 0，随后倍率为 1。负值、和与乘积回绕已接入并验证，见[属性倍率](np560_npe_battle_attribute_multiplier.md)；原厂前端除零异常恢复仍待核对。

上述行动者 `6468` 是当前等级：角色初始等级来自第 12 段 `+35`，
升级后同步更新；敌人来自第 4 段 `+14`。角色 `+58`、敌人 `+29`
分别是第一项仙术。旧《英雄传奇》及《天降风云》字节读数使用错误的 RAM
字节访问位置，不能再作为下限字段的证据。正确隔离开场采样为角色等级 1、
仙术 `4/6/10`，敌人等级参数 9、仙术 `6/0/0`。

敌方走独立的源 `33:6DB0` 计算器：攻防差先加浮动并取低字，下限为等级参数除 5 加 8，没有 999 上限。
伤害高于下限且目标已选择类型 5 防御命令时，乘 25 取低字、带符号除 100；下限分支跳过该减伤。随后再次加同一个
浮动。此前上限及下限减伤结论已撤销；17 条原厂输入／136 个记录阶段通过 C 和实际 SDL，见[带符号规则](np560_npe_battle_signed_values.md)。不能将角色的 `+4`／996 公式用于敌方。角色与敌方计算器均在动作
分派前抽两次随机数，防御、仙术及道具也会消耗，已倒下未行动者跳过。

原厂 `2A:14D0..1566` 还会在结算时从战斗记录当前体力 `+0x50`
扣去 `52:7926` 并处理死亡。当前 C 函数只移植普通攻击的伤害值；
SDL 原型现把该伤害函数接到 Enter／空格普通攻击，并将敌方当前体力扣至 0；
全部敌人倒下接奖励和原事件，失败接败战后续或标题。C 版已收集队员指令
后按当前速度结算，同速保持记录顺序；敌方在其行动时抽普通目标，失效目标
扫描并绕回。敌方仙术、完整状态及逐行动动画仍未接入。
详见[速度队列](np560_npe_battle_round_queue.md)与
[敌方行动修正](np560_npe_enemy_action_reconstruction.md)。

后续扣体及胜利门槛更正见[负体力与胜利结算](np560_npe_battle_negative_hp.md)：菜单正体力判断、排队目标非零判断和侧退出零判断分别保留；数字规则不能用“全部存活／死亡”统一替换。
