# 原菜单异常绘制及旧界面清理

更新：2026-10-08。纯 C11＋SDL2 清理会改编原画面的旧路径，并使 `world.c` 的菜单资源调用保留原错误后的后续绘制。整体粗估仍约80%，其它固件服务及更多NPE适配尚未完成。

## 清理内容

删除四个旧辅助API及其界面：英文标题、旧成员属性预览及包装、旧HP／QI战斗HUD。生产主程序在原属性页面适配器失败时返回失败，取消调用旧预览的分支；游戏标题、人物文字和体／气仍由现有原页面实现绘制。

删除原父菜单金额预绘制使用的自制5×7字库。金额保留主程序已有的原紧凑12字体服务；父菜单只绘制NPE资源及选项反色。旧综合探针只删除针对已移除改编界面的断言，HUD调用换为现用原计数服务；本轮编译该探针，没有重跑其长综合路线。

父菜单、系统／属性／物品／音乐子菜单和存档槽直接使用原驻留UI基址加序号，不再先检查位图总数、签名或固定尺寸。存档槽保留宿主接口的固定文字区域位置界限，绘图资源本身由原服务读取并裁剪。

## 原异常行为

原物理 `4F:1FFA..207C` 的音乐弹窗在 `2022` 调用 `2B:0000` 通用位图服务，随后直接按选择参数调用反色与提交，未检查位图服务返回值。因此，无效索引下仍应反色原LCD，而小图应按实际尺寸绘制。C的资源适配器已保留被调用者的原−1／−3忽略规则；本轮移除阻止调用者继续的元数据检查。

新 `reference_menu_guard.mjs` 恢复原快照，通过原公共输入进入系统／音乐菜单，只在打开音乐弹窗前改变 `52:7AEC`。原NPE、PRG、WASM、包和快照不修改。

每条路径保存原进入前画面、两张弹窗状态和退出后地图画面。C探针附着生产资源运行时，设置相同驻留字，并把C缓存位图总数改为1、缓存头基址改变，证明生产菜单实际使用驻留字而非缓存元数据。
