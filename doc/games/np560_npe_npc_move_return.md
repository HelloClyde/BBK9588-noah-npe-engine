# NPC 连续移动、进度服务与地图返回

2026-10-07。实现仍为 C11／SDL2，使用当前 NPE 的地图、NPC 图组及事件记录。

## 原始证据及差异

原固件 `NP560.PRG`：

- `3C:8B9E`：模式18先绘制地图；`8BA2..8BAA` 随后设置地图初始化标志 `7AB4=1`，然后验证移动事件。
- `4C:4C56..4C62`：模式14设置同一标志并重画当前进度的地图，然后读取事件、写进度和后续模式。
- `37:1328..1366`：返回模式1后，初始化标志非零时，音乐开关等于1则重播保留地图音乐槽；清除标志，再重画地图。重播不重新抽取 RNG。

反汇编片段保存在 `tmp/npc-move-return-original-source.asm`。原运行时为已有本地固定副本 `certified_original_v1`，由参考脚本读取当前 NPE，而不是把 C 输出作原版夹具。

当前 NPE 地图126实际包含以下连续事件：NPC163／图组25移动到(20,14)，后续模式18事件2；NPC164／图组20移动到(22,14)，后续模式14事件3；进度168改为169，返回模式1事件1。参考流程通过原UI保存／加载这张地图；没有改 NPE、NPC 移动记录或图组。音乐开／关分别采样。

原版各32次提交。修复前 C 前30次整屏匹配，却缺少进度服务入口的旧进度地图以及返回模式1的新进度地图，也没有重播音乐。失败日志：`tmp/npc-move-chain-before-fix.log`。只观察模式1出现后的三个推进会漏掉最后一次地图初始化；延长观察后确认该差异。

## 修复

- `NpeWorld.map_init_pending` 承载运行时地图初始化请求，排除在主机存档线格式之外。
- 模式18显示服务在入口地图提交后设置标志；数字终态接口仍按原有接口解析后续。
- 显示服务的模式14后续交给实际主程序调度，先提交旧进度地图，再写新进度。
- 返回模式1时按原顺序重播保留槽、清标志、绘制地图、保留实际提交。已有播放请求也必须重启 SDL 播放游标。
- 数字接口的自动恢复声音不抢先消费显示服务的初始化请求；没有增加地图、NPC 或游戏编号特例。

全部提交逐像素比较 C 索引缓冲与 SDL 实际 ARGB 输出。连续链还验证进度服务提交时仍为168，最后提交已为169；20个 NPC 的位置与方向匹配。两组声音样本均检查原保留槽播放请求次数、请求发生在最后地图提交之前、SDL 游标归零；关音乐时无重播且游标保持。C 种子11保持，不把未定位的原 RNG 字段当作对照。

有限流程使用参数15对应名义141ms等待。真实设备的计时相位未由此证明。字节回绕样本仍只验证275次运行中提交并在主机关闭时中断，不声称其已终止。

旧参考采样中的移动主体像素没有改变。87／39／292次旧计数分别扩展到101／48／297；旧“没有额外地图提交”的结论撤回。原始延长观察还包含个别后续空闲刷新；夹具生成器只取到模式1首次初始化提交，空闲周期不混入移动服务。未来参考脚本明确等到 `7AB4` 清零且已收到模式1地图提交再结束。

十个目标定向构建无编译警告，九项相关回归退出0：连续链、普通返回、原14条移动、事件返回、字／字节回绕、驻留缓存、标题读档、开场短段、问答驻留／存档。记录见 `tmp/npc-move-return-regression-build.log`、`tmp/npc-move-return-regressions.json` 及各目标日志。

复现参考／夹具：`reference_npc_move_chain.mjs`、`reference_npc_move_return.mjs`、原三个移动参考脚本及 `generate_npc_move_chain_fixture.py --kind return`，均位于 `npe-sdl/tests/`。实际控制器探针为同目录 `sdl_npc_move_chain_probe.c` 和 `sdl_npc_move_return_probe.c`。
