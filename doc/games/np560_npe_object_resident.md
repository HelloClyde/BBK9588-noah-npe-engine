# 地图物件驻留共享（2026-10-08）

## 实现

纯 C 运行时绑定原地址 `52:759E..75DD` 的八个物件槽，共 64 字节；并把 `52:742C..74F3` 的 200 个拾取标志绑定到现有保存状态。World 共享地址逐字节计数增加至 3176。

原装载器 source `29:BFBA..C130`（runtime `0C:BFBA..C130`）将每个十字节 NPE 文件记录重排成八字节驻留槽：

| 槽偏移 | 内容 | NPE 文件偏移 |
| --- | --- | --- |
| 0..1 | ID，大端 word | 0..1 |
| 2..3 | 原样保留的 word，本轮不赋予新语义 | 4..5 |
| 4..5 | 物品号，大端 word | 2..3 |
| 6 | X | 6 |
| 7 | Y | 7 |

文件末尾两字节被原装载器读取后丢弃。换图、暖恢复和重新开始均重写全部八槽；没有出口表那样的保留填充字节。地形清除、巡走避让、主角碰撞和拾取选择读取这份驻留表，运行时修改不再依赖修改 NPE 文件。

拾取选择器 source `46:CE22..D0B8`（runtime `29:CE22..D0B8`）在第一个 ID=0 的槽处立即返回 FFFF；坐标不匹配才继续扫描。修正了原 C 跳过零 ID 后继续扫描的行为。物件拾取的坐标分别比较 X/Y；没有把出口使用的线性坐标规则套到物件选择。

## 验证证据

- 16 组原公共 UI 装载：地图 1、80、9、18、91、37、120 的系统／标题读档，以及新游戏／空槽；合计 1024 个原驻留字节与 C 一致。
- 16 条原公共输入路径：库存 0、98、99、100、32767、32768、65534、65535；标志 1／2、方向 4／255、首零槽截断、末槽有效、先匹配已拾取、保留 word 改写。实际原版运行时加载地图 80 后仅注入驻留 RAM，未改 NPE 或 PRG。
- 10 条发生拾取的路径共取得 20 次原版地图／提示 LCD 提交；实际 `main.c` 的 C 缓冲与 SDL 读回逐像素一致。十次 C 提示结束后的恢复画面另验证与所保留地图一致，没有算入原版提交的通过数量。
- 每条公共路径比较结束 64 字节物件表、200 字节标志，以及模式／事件／地图／进度／方向／视口／数量。重复拾取没有新增画面提交或改变数量。
- 部分 word、相邻槽非对齐写入、物品缓存至标志的相邻写入通过；直接 World 越界整段写入在修改前拒绝。
- 自身 NPESAV22 的物件缓存不增加线格式字段；暖恢复／重新开始重载缓存，200 个标志的保存／读取通过。
- 旧拾取 12 数值路径、29 次 C/SDL 提交与定时／关闭、53 个地形覆盖容量及旧自身存档迁移保持。NPC 15 条巡走改从物件驻留 RAM 注入避让坐标；出口 16 组装载／13 路径直接 127＋main 127、队伍传送 16 组装载、资源 58 条完整 128KiB RAM 路径通过。
- 9 个目标最终构建无警告，8 项必要短检查退出 0；原五项文件和三张字库哈希保持。

参考脚本、C 探针及冻结报告：`npe-sdl/tests/reference_object_record_load.mjs`、`reference_object_public.mjs`、`object_record_load_probe.c`、`sdl_object_public_probe.c`、`tmp/object-resident-report.json`。原 LCD 和 C 缓冲各保存 20 份独立文件，报告保存 SHA-256。
