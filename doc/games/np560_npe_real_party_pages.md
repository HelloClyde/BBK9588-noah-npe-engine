# 三名原角色页面与菜单人数缓存

更新：2026-10-07。生产程序仍为纯 C11＋SDL2；当前 NPE 提供角色名称、肖像、属性、装备与技能。PRG／WASM只作为离线参考。

## 人数缓存的实际差异

原主菜单初始化 `49:0022..0070` 将驻留 `7AB0` 设为1，再分别检查第二／第三记录的 `6A85/6B19` 是否恰好为1；符合时各加1。第一个记录不参与人数判断。状态／穿戴页的 `36:3B06..3B5A`、`36:4F24..4F7C` 使用这个缓存，上下修改连续的记录索引，不重新扫描活动标志。

旧 C 每次上下键按非零活动标志重新计数。已用原版短流程复现：打开菜单后再把队员标志设成三人，原菜单缓存仍为1，Down不提交；C却多提交一次。日志为 `tmp/real-party-before-fix.log`。

现在运行字段 `menu_party_count` 在打开主菜单时按原规则计算，页内继续使用它；暖读档保留，C冷初始化清零，NPESAV15不增加字段。标志值2不等于1，不能因非零而计入该菜单人数。

原页只依人数缓存选择连续记录。因此诊断 `[1,0,1]` 在菜单打开前设置时，人数是2；Down选择第二记录，即使它的活动标志为0，也绘制这个记录，不跳到第三记录。状态及穿戴显示服务已移除活动标志过滤，继续校验角色编号与当前NPE资源。物品使用／装备等行动入口的活动判断未由这个显示服务替代。
