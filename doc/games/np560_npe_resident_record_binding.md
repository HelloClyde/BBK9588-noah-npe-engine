# 地图与战斗人物记录的地址绑定

2026-10-08。新增纯C客机记录读写接口，并接入实际入战保留和离场复制流程。十三组原装载函数的隔离对照中，六份战斗记录及三份地图记录均逐字节匹配，地图／战斗体力、ID和装备分别保留。位图主循环仍未调用新装载服务，其余驻留内存区域也未全部绑定；图号31实际游戏路径仍待完成，工程粗估约80%。

## 生产实现

`npe-sdl/resident_records.inc`由`world.c`包含，提供：

- `npe_world_map_record_image`：读取当前地图人物的148字节表示。
- `npe_world_record_write`：更新一份物理记录中的指定字节，再更新被写到的命名字段；只写一个字节时保留该字所在字的另一字节。
- `npe_world_resident_records_read`／`write`：按完整客机地址访问记录，可跨多份人物记录。

| 客机范围 | 内容 |
| --- | --- |
| 52:6450..67C8，结束地址不含 | 六份战斗记录，共888字节 |
| 52:69C6..6B82，结束地址不含 | 三份地图记录，共444字节 |

入战前捕获地图共享字段到运行时`battle_map_records`。战斗中体力、气、等级、装备、技能槽及基础属性的宿主活动数组代表战斗副本；地图读写使用保留副本，地图姓名、图号、方向和状态仍有独立所有者。战斗人物ID另存，物理人物前缀数量在入战时捕获，不会因地图活动标志被覆写而重新划分敌方槽。

实际离场的148字节复制改用该写入口，按原顺序复制后再写战斗末尾标志；装备状态重建读取地图装备副本。新增副本和前缀字段只在运行时使用，自身NPESAV22格式不变，已有旧格式迁移及正常存读恢复回归保持。

新目标`battle-bitmap-world-probe`运行生产C装载服务和记录绑定，以已有十三组独立原函数的完整128KiB RAM／84字节调用记录为参考。文件读取实际写入目的内存，并将两个记录区的交集交给生产绑定入口；随后比较六份战斗和三份地图记录与原结果。

- 十三组完整RAM和调用记录保持匹配，十三组各1332字节人物表示匹配。
- warm-31的35328字节读取覆盖九份记录，C的活动体力、地图／战斗ID及装备从对应原字节取得。地图记录加载不会用地图体力覆盖活动战斗体力。
- 使用该原结果中不同的地图／战斗体力字节，检查分两次单字节写入、两个物理所有者隔离及记录区边界拒绝。这是C绑定的边界检查，不是另一次原函数采样。
