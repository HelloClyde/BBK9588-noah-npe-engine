# 驻留库存与资源缓存的地址绑定

更新于2026-10-08。生产代码为`npe-sdl/resident_resources.inc`，接口为`npe_world_resident_read/write`。在已有[人物记录绑定](np560_npe_resident_record_binding.md)上，将按地址发生的读写连接到库存和缓存的实际所有者。

## 已连接的区域

以下范围均为左闭右开，地址按客机段位记法表示。

| 区域 | 地址 | 字节数 |
| --- | --- | ---: |
| 六条战斗记录、255个库存字、三条地图记录 | 52:6450..6B82 | 1842 |
| 仙术缓存、道具缓存 | 52:730E..742C | 286 |
| 道具缓存编号 | 52:7A72..7A73 | 1 |
| 仙术缓存编号 | 52:7A74..7A75 | 1 |
| 道具说明长度 | 52:7ABA..7ABC | 2 |

每例共2132字节。库存与说明长度按大端字读写；单字节写入保留另一个字节，缓存保留未触及的尾部。缓存字节是所有者，已有道具／仙术解析器从它们生成字段视图，不因地址写入重新从NPE加载。

接口支持同一连续区间内跨记录、库存及缓存边界的操作；非零长度请求超出上述区间时预先拒绝。长度0无需有效数据指针。其它RAM尚未连接。

## 相邻地址的共同所有者

- 52:67C6..67C8同时是战斗槽5末尾两字节及库存有符号索引FFFF。原来的`inventory_prefix_word`成为这两个字节的共同所有者；人物记录写入及行动标志更新均保持一致。
- 库存索引255为52:69C6..69C8，与地图物理槽0姓名前两字节重合；地图姓名更新与库存读写相互可见，独立战斗姓名不随其改变。
- 52:739E为仙术缓存结束与道具缓存开始的边界，跨界部分写入分别进入两个缓存，保留未写字节。

这些运行时连接不改变本程序NPESAV22的文件格式。原机存档互通已取消。

## 验证结果与复现

`battle-bitmap-memory-probe`复用十三组独立原函数快照，使用原装载器的诊断IO／绘图适配器。每例仍比较完整128KiB RAM及84字节调用记录，并读取生产接口的2132字节、255个库存数值及九个人物记录；全部逐字节一致。十三例共核对27716个绑定字节。

warm-31另检查人物／库存边界、库存255／地图姓名、两个缓存交界的部分写入、区域边界拒绝和零长度操作。这些是采用已观察原字节的C边界检查，没有增加独立原机采样。

四项必要SDL回归通过：道具16张及装备3张、仙术16张、商店实际主程序路径、完整人物字节172张。道具和仙术探针改为经生产地址接口初始化缓存，随后使用已有实际SDL显示流程。六目标构建无警告，五项原始资源哈希保持。

```text
cmake --build npe-sdl/build --config Release --target battle-bitmap-memory-probe npe-sdl
npe-sdl/build/battle-bitmap-memory-probe.exe tmp/tjfy-world-probe.npe
python tmp/finalize_battle_bitmap_memory.py
```

汇总为`tmp/battle-bitmap-memory-report.json`，原快照为`tmp/battle-bitmap-service-native/report.json`，日志前缀为`tmp/battle-bitmap-memory-`。
