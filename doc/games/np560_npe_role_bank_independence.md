# 地图与战斗人物记录的独立内存

## 问题与修正

地图人物有三份148字节记录，起点52:69C6；战斗区有六份同长记录，起点52:6450。上批任意128KiB RAM导入会把两区的ID、装备、等级、体／气和属性合并：首次入战前，战斗读取按地图宿主字段重新合成，战斗写入也修改地图的共享数字字段。地图活动人数变化后，还会重新解释战斗记录。

`npe_world_battle_record_image`现在在宿主尚未安装战斗视图时读取独立战斗区残留字节，首次入战之前也适用，不再取决于地图模式是否恰好为3。库存前置word52:67C6保持其独立所有者。`npe_world_record_write`写战斗ID只修改战斗ID；宿主共享数字只接受当前活动分区的更新，未活动战斗区不改变地图人物。活动战斗时地图数字留在地图物理副本中。

已有入战的地图→战斗拷贝、战斗行动、离场战斗→地图拷贝保持；没有新增替代角色、图号或剧情数值。完整暖构造／读档的战斗区保留范围、异常人数和全部记录写入者仍待核对，不把本批修正声明成完整共享RAM已完成。

## 完整RAM对照

沿用未修改CPU25:3082/type2与2F:E15A的23组原始任意RAM参考。每组经全部3556字节World绑定导入，先比较初始128KiB，再调用实际World周期服务并比较最终128KiB。地图状态和活动人数1／2／3的战斗视图分别通过，共92次。宿主活动人数在这项诊断中由夹具指定，不证明原7AFA的全部控制字段已绑定。

上批一次导出再导入后仍失败的23组参考也经直接完整导入通过，共115次旧参考对照。原始参考与曾失败的日志不修改。

新增`reference_map_tile_update.py --banks`从相同原函数捕获10种地形地址写入：两区体力、ID、姓名，战斗基础攻击、地图装备、地图末位活动标志，以及战斗末尾／库存前置word。原函数执行区与实际缓存函数逐字节核对未修改，栈／诊断检查保持。在地图和1／2／3人活动战斗视图中的40次主World派发，完整初始／最终RAM一致；证明点写入不会连带改变另一物理分区。

这些是33种诊断操作、155次C运行时对照，不能写成155种独立原函数样本。没有证明所有148字节字段的全部动态写入路径、活动人数0／255或完整IO／LCD时序。

## 失败与修复记录

首次重建纯核心位图探针暴露较早的链接问题：`rpg_runtime.inc`依赖World物件函数。地图装载清除改为读取实时八个驻留物件、标志和宽度，消除该反向依赖。普通地图短检查保持；原type1的完整循环顺序及地址重叠仍需继续核对。

旧位图内存探针还把52:742B跨到742C视作越界，当前已接入连续物件标志所有者，旧断言失效。改为验证连续写入和恢复，并在实际绑定末尾52:75DD保留越界拒绝／不修改检查。原参考未改变。

两项战后探针及主行走入战探针先失败。单独编译哈希一致的上批world.c／rpg_runtime.inc，三项失败均复现；行走基线首次因独立输出目录缺字体未到检查，复制相同字体后复现相同多余提交，记录分别保留。

战后夹具漏了原参考在入战前将地图敌群记录7626、7627写51的操作；后来只改宿主敌人ID，不能改变当前实际绘制使用的驻留姿态。按原参考恢复两byte的设置。行走夹具在重建World后只恢复声音观察者，漏了范围观察者；补齐相同运行时回调。原按键、NPE与LCD参考保持，最终相关七目标重跑全部通过。

5187份旧证据逐项SHA256保持。初始失败、基线编译和最终检查都保留在`tmp/role-bank-*`，汇总为`tmp/role-bank-report.json`。
