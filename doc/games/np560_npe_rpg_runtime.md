# RPG客机RAM资源运行时接入（2026-10-08）

## 生产改动

`npe-sdl/rpg_runtime.inc`把原堆／资源装载／客机位图解码连接起来。运行时由当前`NpeFile`拥有，保存51／52段128KiB RAM、文件游标和堆服务；`npe_free`调用清理释放。它不放在`NpeWorld`里，按值复制游戏状态不会复制堆所有权，也不进入NPESAV22。

开启运行时后，先经原C服务分配四块256字节启动缓冲、7000字节地图缓冲及32768字节战斗资源，使用当前NPE段表写入目录／载荷位置，并真实读取第9段驻留资源。每次绘图使用当前RAM指针、实时文件游标、原句柄0回退、短读尾部保留及原三种客机绘图入口。文件名、标题和载荷未硬编码为《天降风云》。

`npe_world_resources_open`显式绑定有写权限的游戏状态。当前已映射的2132字节人物／库存／缓存地址从活状态读取，文件读入这些地址时逐字节更新原所有者；其它字节保存在RAM。接口无需去掉渲染函数的const限定。绘图若收到另一份世界快照，会拒绝跨世界写入；独立只读资源API在未附加运行时时保留原接口。

主程序的标题／新游戏／读档／行走预览及战斗预览在创建SDL窗口前开启运行时。战斗场景、人物姿态／换姿态、控件、光标、目标指针和命令菜单的战斗位图调用已经改走实时服务；`--battle-assets`也经新运行时与`draw_pixels`提交。敌人图像、动画组、地图等使用其它资源服务，其管线尚未全部移植。

## 原函数联合证据

`npe-sdl/tests/reference_rpg_runtime.py`直接执行未修改的堆初始化／分配／锁定／解锁／释放／整理、启动分配前缀、7000／32768分配、驻留读取、原战斗位图装载及原三绘图函数。CODE总线检查覆盖这些原函数。保留边界为文件seek／read的NPE字节供应、分配失败提示，以及三个分配前缀结束后的返回。

输入是明确清零的诊断RAM，不预置捕获堆头；显示指针种入540000。文件供应放在400000／410000区，避免占用30／31段原堆代码。此前供给300000覆盖了30段原服务导致首分配失败，已移走供应地址并增加原堆代码校验。

八组覆盖驻留1／29、外部514／31／34／512及实际查看器起点1／514。图号31真实读取35328字节，跨入人物／库存／缓存，再运行实际原绘图函数；它的这一读取／绘图边界已通过，后续游戏执行未因此自动通过。

`rpg-runtime-probe`对每组分别用无绑定RAM、有活世界绑定的RAM运行，共16条路径。每条全部131072个RAM字节、28800像素、真实文件游标和分配失败计数一致；实际SDL的28800个RGBA像素也一致。额外验证主机修改体力能从客机地址读出、客机写体力能进入活游戏状态，显示和状态采用同一所有者。

同探针调用真实`npe_app_main --battle-assets`入口，经真实文件读取、初始化、窗口、绘图和退出。SDL_QUIT由探针在提交时注入；本次16次缓冲提交均与原查看器图1结果一致，程序退出0。提交数量受SDL窗口事件影响，不作为固定时序标准。

`sdl-rpg-runtime-item-probe`复用已有七条原道具战斗路径，在行动前附加活资源运行时。93次完整C／SDL画面、88个阶段状态、142字节缓存、66个战斗字段及结束状态检查通过。它的入场快照在附加前准备；这一事实不能推广为全部启动／入场已验收。
