# NPE 开场与场景动画：绘制、声音和逐帧等待

2026-10-07。生产程序使用当前 NPE 的第 13／14 段场景图像和第
16～19 段声音，以纯 C11／SDL2 播放。默认打开文件先播开场，再显示
原 NPE 标题。没有写入《天降风云》的图片、文字或游戏 ID 特判。

## 原厂调用与声音

- source `3C:D45C..D492` 调用场景组 1，坐标 (0,0)，绘制／清除均为 0；
  随后 `D4AE..D4B6` 进入静态标题 7。开场不会随标题刷新重新播放。
- `41:AEFA..AF1E`：组 1 固定声音槽 0、不抽随机数；其它有效场景
  抽一次共享 RNG，取 `1 + roll % 3`。抽取发生在音乐门控前，关闭音乐
  仍消耗它；`AF22..AF28` 的门控是值等于 1，而非任意非零。
- 原厂资源槽对应当前 NPE 段 16～19；`AF2C..AFAA` 传入空循环回调，
  是有限播放。`B0D4` 场景末调用停音，即使关闭音乐也执行。
- 无效组／绘制／清除参数在 `ACCA..ACF8` 被拒绝，不选曲、不绘图。
  模式 15 调用者忽略这个资源返回值，继续当前文件的后续事件。
- `npe_world_sound_scene_start` 执行选曲；`play_scene_group` 在验证资源后
  起音，提交各帧，末尾停音。缺失资源不替换为另一个场景。

原厂算术的 UDIV 余数含义已有 15 个独立 CPU 输入的证据，见
[声音请求](np560_npe_sound_requests.md)。本次沿 `41:AF12..AF18` 的同一
余数运算核对 C 场景选择，覆盖 15 个 roll、3 个组、门控值 0／1／2
共 135 种组合；不是新跑了 135 次原厂 CPU。

## 原厂绘制

`41:AFE4..B084` 分派 `03:42C0/42C4/42C8`。原 packed-nibble 服务
source `2A:7C34/7ECE/8232` 分别执行：

| 绘制模式 | 像素写入条件 |
| --- | --- |
| 0 | 全部替换，包括源颜色 0 |
| 1 | 仅当原 LCD 的目标颜色为 0 时填入源颜色 |
| 2 | 源颜色非零时覆盖目标 |

图像尺寸来自资源，位置使用服务的 X／Y 参数，图像头的 X／Y 不参与
这三个服务的位置计算。C 的 `npe_render_scene_animation_frame` 保留当前
LCD 并就地合成；撤销此前每帧重绘地图、模式 1／2 共用透明条件的实现。

模式 1／2 的清除参数 1 在 `B01E..B038` 调用选择缓冲、清屏和显示提交，
**每帧先提交一张空白屏，再提交动画图像**。模式 0 忽略清除参数。
原厂与实际 SDL 均核对了这两次提交，不能只统计带图像的一次。

## 等待参数与输入

原厂 `03:4120` 跳转 source `50:317E`，把帧等待参数 20 乘以 10，
再经 `4B:FC6A` 和 `4E:7286` 设事件计时器。计算
`max(1, floor(200 * 64 / 1000))` 得到 **12 个 64 Hz 计数**。
SDL 现用名义 187.5 毫秒向上取整的 188 毫秒等待，替换旧 20 毫秒。

`4B:FCB6..FD5C` 接受原方向／确认／返回／菜单键并提前结束本帧等待；
场景函数忽略返回值，接着播下一帧。SDL 消耗对应按键，只结束本帧等待，
不跳过全部动画；无关键及 KEYUP 不结束等待。主机关闭窗口则停音并退出，
不执行场景后续剧情。主机的 Space、KPEnter、Esc、Backspace 沿现有键盘别名。

**`3C:D498` 的 4000 不是开场结束后再等四秒。** `03:4154` 跳转
`31:71D2`，设置周期服务计时器；已由原
[4 秒追击服务](np560_npe_chase_group10.md) 接入。开场后初始化该截止时间，
随即进入静态标题。

上述参数有源指令和硬件时基证据；测试用可控 SDL 时钟验证回绕、期限和
输入消耗。原厂捕获的 `displayCommitStepsPerSecond` 仍为 0，不能用其
步骤偏移换算毫秒。物理 tick 相位、绘图执行耗时、键盘重复／去抖和
整机其它事件服务没有通过真实设备时序验收。其它动作等待也尚未一并改写。

## 验证范围与计数

`tests/reference_scene_animation.mjs` 从隔离原厂战斗快照进入普通地图，
保留原显示；只修改临时 RAM 参数，以原模式 15 播场景。PRG、NPE 和
剧情诊断存档均不修改。开场参考调用的参数与原开场调用相同，但不是
原厂冷启动全过程的捕获。

| 原厂参数组 | 对照的动画／空白提交数 |
| --- | ---: |
| 开场组 1，绘制 0／清除 0 | 62 |
| 局部组 2，绘制 0，清除 0／1 | 12 + 12 |
| 局部组 2，绘制 1，清除 0／1 | 12 + 24 |
| 局部组 2，绘制 2，清除 0／1 | 12 + 24 |
| 结尾组 3，绘制 0／清除 0 | 37 |
| 合计 | **195，去重 120 张** |

原厂捕获还含部分转标题提交，本项只截取上述明确的场景提交。
`tests/sdl_scene_animation_probe.c` 检查合成后的 C LCD 与真实 SDL
`SDL_RenderReadPixels`；另外播放地图 73 的当前 NPE 原记录 24 次，
以及实际主程序默认启动的 62 次开场，合计 **281 次比较零差异**。
地图 73 后续是故事 50，地图 107 的零组记录仍接当前文件事件 14／2。
实际默认启动核对开场段 16 的有限请求、不抽 RNG、末尾停音再进标题；
主机关闭的场景与开场路径也检查。第 16～19 段候选 PCM 的最后六字节
与回调输出相同，后续十字节静音，有限播放不会自动重来。

本项使用原厂进入前 LCD 夹具，因此不证明更多地图／菜单的底图绘制。
结尾 37 帧复用了已核对的场景；195／120 独立统计，不加到既有静态
334 张、战斗 2119／723 或剧情 77／77 中。281 包含重复播放，不当作
新增 281 张不同画面。

旧菜单／局部路线探针通过 `scene_wait_input.h` 为每帧提供原有效确认键，
完整绘制开场但缩短等待；不把这些旧探针作为播放时长证据。告别、音乐
弹窗、属性菜单、三槽存档及声音调度回归通过；全量构建和 ctest 5/5 通过。
四款原始中文路径在新开场接入后继续通过 12 项打开／声音／安装字库／
标题／存档检查，见[主机路径](np560_npe_host_paths.md)。
