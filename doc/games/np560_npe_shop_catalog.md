# NPE商店的驻留目录与物品扫描控制

更新：2026-10-09。纯C／SDL实现继续按原资源和固件行为复刻，整体仍约80%，完整引擎未完成。

## 原代码与修改

原3F:B50E..B530把7A14设0、7A10设1、7A12设254。买入入口3F:B54E..B702清255字节6DBA..6EB8，按当前NPE商店记录设置有效ID的存在字节；卖出入口保留旧目录。目录不是每次选择或绘制都重新从NPE生成。

原4B:E53C..E69A先将起始ID截成byte，再加方向，按实时7A10／7A12检查候选范围。7A14非零时只检查有符号库存是否正数；否则7AC2非零时加载正库存物品并检查有符号缓存价格，买入分支则读取6DBA的存在字节。存在字节和7A14均接受255等非布尔值。

此前C每次从event_context_id重读NPE目录，使用固定1..254范围，且没有7A14分支。因此原RAM修改目录、上下界、库存扫描模式或入口后更改context时，C不能保留原行为。

现在World拥有255字节目录，新增三个控制byte，并接入实际运行时双向读写。World绑定由3772增至4030字节。买入入口读取NPE并重建目录，卖出入口保留；候选扫描和实际列表／翻页绘制使用驻留内容。暖新游戏与暖读档保留目录及控制，自身冷解码按冷初始化清零；自身NPESAV22／NPESAV23载荷保持不变。尚未进入商店的独立资源预览仍可通过现有NPE目录API查询。

修改前8条核心路径全部失败，含缺少目录／控制接口；修改后8条一致。首次SDL翻页对照仍有167像素差异，原因是文字列表绘制还直接读取NPE目录；接入驻留目录后34次提交全部一致。初始构建及失败日志保留。

## 原标题采样的限制

人工把旧战斗快照强制切到标题的三组采样，目录所在7000以下RAM在读档后出现定位异常，不能证明保留或清除。它们及较晚人工重开结果保留，未计入通过。另用已有正常启动方法进入原标题后采样两组，完整目录保留已独立核对。系统路径三组及新游戏早期六组也分别核对，不把正常标题结果推广到人工强制路径。
