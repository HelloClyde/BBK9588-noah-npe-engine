# 商店调用共享道具记录的顺序

更新于2026-10-08。本轮接入已建模的7A72编号和739E起的142字节道具记录，按原程序区分目录绘制、卖出筛选、说明和交易的读取入口。整个NPE引擎仍未完成。

## 原程序与实现

- 买入列表按当前NPE目录找编号；上下移动不装载共享道具记录。原3F:DECE／DF24直接复制资源名称、价格到独立缓冲，不能用共享缓存名称代替。
- 卖出入口3F:B8DE..B94A扫描1..254，库存为正的有符号词才装载记录，再测试缓存价格；找到七个候选就停。C不再为了构造整个列表而额外装载后面的道具。
- 4B:E53C相邻候选服务在卖出模式对每个正库存候选调用共享装载；买入模式只查目录。向前翻页继续找六个，向后翻页先找前项再补后项。保留最后实际调用留下的记录。
- 原40:C5CE的向后补项会写入FFFF并继续到六次；资格变化时可产生选中／末项FFFF、行号6。C保留这个结果。
- 数量弹窗49:573E和交易确认3C:4A6E调用共享装载，当前编号相同就沿用旧记录。交易用缓存价格；列表仍显示当前NPE资源价格。
- 售空后的调整按原交易分支调用相邻候选，没有预先同时寻找前后项。说明翻页接入同一装载入口；被现有页界拒绝的键不额外装载。
- 3D:F056..F06A在选中FFFF时提前返回，位置在道具行和新光标绘制之前。即使旧首末编号仍有效，也不能画出这些行。

资源名称、图像与目录仍来自当前NPE，没有天降风云专用常量。缓存不加入NPESAV19。

## 原运行器短路径对照

原参考使用未修改的原引擎WASM，从已有商店快照恢复，设置诊断库存、金钱和142字节驻留记录，不替换道具或UI服务。每个场景由独立Node进程执行。

| 场景 | 原LCD提交 | 核对结果 |
| --- | ---: | --- |
| buy-stale | 4 | 驻留道具45价格20，列表显示资源价格10，买入实际扣20；缓存名称与说明沿用 |
| buy-fresh | 7 | 列表移动不装载，打开数量层装载选中道具，取消保留记录 |
| sell-price-zero | 1 | 驻留价格0拒绝唯一商品，选中FFFF，旧首末45／54保留，没有商品行 |
| sell-rejected-first | 2 | 首项先被缓存价格拒绝；向上重新装载后资格变化，补项产生FFFF／行6 |
| sell-window | 15 | 七行入口、上下移动及跨页扫描顺序；最终缓存不一定等于选中编号 |
| sell-remove | 8 | 连续售空首项和末项，余额、库存、列表边界及后续装载编号一致 |
| 合计 | 37 | 每次整屏28800像素、SDL实际读回、缓存编号及全部142字节零差异 |

每次提交还核对余额、目标库存、模式、上下文、选择／窗口、数量／确认项、说明长度与页界。驻留键字写入只有观察到提交及状态变化才说明对应分支执行；没有提交的阶段不作为原公共输入送达的证明。

新增探针复用实际C主循环，保留SDL纹理和软件渲染，使用诊断时间及键输入。验证不包含物理设备完整时基或正常属性全程游玩。
