# 商店的资源行、缓存选择与光标边界

更新于2026-10-08，接续[共享道具缓存调用顺序](np560_npe_shop_item_cache.md)。本轮消除用派生显示目录代替原选中编号的问题，并补齐窗口内FFFF、行号回绕和LCD边缘裁剪。整个引擎仍未完成。

## 选择与显示分开读取

原商店至少有三种不同读取规则：

| 用途 | 原依据 | C实现 |
| --- | --- | --- |
| 卖出入口／相邻候选 | 正的有符号库存，调用共享记录，再检查正的有符号缓存价格 | 直接维护原首项、末项及选中编号 |
| 卖出商品行 | 3D:F140..F1D0检查正库存和非零资源价格 | 只枚举当前编号窗口，读取NPE名称／价格 |
| 数量说明／确认交易 | 49:573E／3C:4A6E读取选中编号的共享记录 | 直接使用`shop_selected_item`，不依赖显示行索引 |

当前NPE的146号资源价格为0，诊断驻留缓存价格20时仍能被原引擎选中；它没有商品行，但图标、现有数量、光标和交易入口仍存在。只有这个商品时，交易沿用20的缓存单价，卖出一件得到10。若入口后又装载148号，打开146号数量层时会重新读取其零价资源，交易不增加金钱。C按这些调用关系处理。

列表重画才按实际显示行重新计算光标行；窗口内上下移动直接对7A46字节加减。显示目录索引只用于宿主辅助信息，不能决定原选择是否存在。

## 窗口内FFFF与未移动的搜索

- 40:C3D8和42:5CAC在已有窗口内直接写入相邻服务结果；即使返回FFFF，仍更新图标、数量和光标并提交。跨窗口未找到候选才不提交。
- 图标寻址是原7AE4加完整选中词，再按16位回绕。C从当前NPE的道具图标区取得基址，没有游戏专用基址常量。当前参考基址1492，FFFF对应1491号图片。
- FFFF在库存寻址中是有符号-1，读取52:67C6，位于255个库存词之前。新增`inventory_prefix_word`保存该词；原诊断值321的实际光标画面已与C／SDL对齐。
- 未移动的搜索也可能装载另一道具。主程序登记新的运行状态并保留LCD，不因缓存变化额外重画。
- 行号按字节回绕；旧光标矩形和新字形按屏幕边界裁剪。原诊断0→255和7→8→7已对照，不把异常行号当成SDL退出错误。
- 活动卖出显示只读取首末编号之间的记录，选中FFFF提前返回；输入派发撤掉无用的全库存枚举。

## 原运行器与C／SDL对照

沿用未修改原引擎WASM、已有商店快照和诊断库存／缓存设置。新增两条行号路径只在指定键前诊断写入7A46，保留原LCD平面；C探针在相同阶段写入该字段及宿主显示状态，随后实际主循环处理输入。

| 场景 | 原LCD提交 | 核对重点 |
| --- | ---: | --- |
| zero-resource-only | 4 | 没有商品行仍选中146，沿用缓存说明／价格并售空 |
| zero-resource-later | 6 | 后项装载使146重新读取零价；窗口内找不到前项后写FFFF；库存前词321 |
| zero-resource-before | 3 | 先装载前项后拒绝146，未移动分支保持LCD |
| zero-resource-window | 15 | 首项缺少商品行，移动行号仍逐字节变化；跨页重算行，末次搜索换缓存而不提交 |
| zero-resource-paging | 6 | 100字节GBK缓存说明的右／左翻页，随后交易 |
| zero-resource-negative-cache | 1 | 负缓存价拒绝唯一库存，旧列表边界保留 |
| zero-resource-row-underflow | 3 | 窗口内FFFF，行号0减到255，保留屏幕内旧像素 |
| zero-resource-partial-cursor | 3 | 7加到8只显示字形顶部，再减到7；矩形／字形底边裁剪 |
| 合计 | 41 | 每次28800像素、SDL实际读回、缓存编号与全部142字节零差异 |

每次提交核对模式／上下文、余额、目标库存、选择和窗口、数量／确认项、行号、说明长度和页界、库存前词。每个输入阶段还对照缓存，包括没有提交但缓存改变的阶段。驻留键字没有提交的阶段仍不计原公共输入送达证明。

独立原生命周期短验证三条：新游戏、系统暖读档、标题暖读档，67C6均从321保持到321。C对应服务检查通过；冷主机读取／构造为0，字段改变不影响NPESAV19任何字节。后三项是C服务与线格式检查，未扩展为原物理冷启动证明。
