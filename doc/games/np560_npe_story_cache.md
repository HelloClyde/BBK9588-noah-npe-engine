# 模式14剧情事件驻留表及编号处理

2026-10-07。依据原 PRG 及已有本地固定原版运行时 `certified_original_v1`，不改写游戏剧情。

## 固件记录和原差异

`29:EAA2..EBD2` 访问15个驻留槽，只读入当前地图第11组提供的前项；未提供的槽保持原值。每条文件记录7字节，文件编号被消费但不进入服务字段。

RAM 表基址应为 **74F4、步长6**：下一事件字在+0，进度字在+2（74F6），模式字节在+4（74F8），+5未使用。不能把进度字段74F6当作完整记录起点。C 保留原 `NpeMapStoryEvent` 中的文件编号／指针作为元数据，服务 getter 只返回槽号及已缓存字段，不依赖这些元数据。

`4C:4C6E..4C80` 先把事件号截为低字节，再检查1～15；`4C:4C84..4C8C` 的非法编号写模式0，保留进度和事件字。有效编号按槽读取，和当前地图提供几条记录无关；冷零槽也是有效槽。显示服务先提交旧进度地图，模式1初始化再提交新进度地图。

修复前 C 每次地图装载清空15槽，并使用文件记录数限制服务。非法编号不改变模式14，会让实际调度反复提交入口地图直到64跳上限。原代码还扫描未知尾部字节猜测剧情表，固件没有这一步。

反汇编片段：`tmp/story-cache-original-source.asm`。静态当前NPE统计：147张地图，第11组数量为0／1／2／3／4／5／6／8；未找到提供15条记录的该游戏地图。

## 实现

- 新增独立剧情缓存装载及查询函数，地图只覆盖前项；`story_event_count` 作为当前文件数量，不作为服务槽位上限。
- 暖读档、暖新游戏从现有15槽出发再装载目标地图；冷主机解码从自身的零状态装载。主机档不序列化驻留缓存，NPESAV17格式不变。
- getter 取事件低字节；模式14非法编号写模式0，交由现有显示调度返回地图，避免64次重复绘图。
- 当前格式直接按目录第11组解析，未知／损坏目录返回错误；撤掉从其它字节猜表的逻辑。短尾兼容路径保留缓存，其行为不作为原机旧格式已验收的证据。
- 进度／地形更新和后续模式仍读取缓存，不增加游戏编号或事件编号特例。

## 原动态证据

`reference_story_cache_load.mjs` 在原UI保存／加载当前NPE地图2／9／1，分别提供0／1／8条记录。系统和标题各三组，加暖新游戏和标题空槽两组，共八组。加载前诊断15槽为不同进度／后续及未用字节。原结果明确显示：只覆盖提供的字段，未提供槽保留；未用字节也没有被 loader 清除。

C 的15槽服务字段在八组中全部匹配。这里只建模参与服务的字段，没有把未用字节或文件编号当作运行时规则。

`reference_story_dispatch.mjs` 在当前NPE资源上执行七条短流程：

| 原输入／记录 | 结果 |
|---|---|
| 事件15，当前地图只有8条记录 | 执行诊断保留槽15，进度33，后续1／71 |
| 事件271 | 低字节15，得到同样结果 |
| 事件0／16／256 | 不改变进度1或事件字，返回地图 |
| 槽15三字段为零 | 写进度0，再经模式0返回地图 |
| 槽15后续模式25、事件77 | 写进度33，调度归一为模式1，保留事件77 |

七条共14次原LCD提交，C索引画面和实际SDL ARGB逐像素零差异；提交顺序、进度／事件／模式、地图初始化标志和C种子11保持通过。开音乐的保留槽场景，槽22在最终地图提交前重播一次，实际SDL游标归零；关音乐场景无重播且游标保持。没有把C种子当作原冷启动RNG证据。

初次参考采样第三条之后出现两份相同RAM候选，已通过原F4菜单变化筛选实际活动银行并恢复菜单；沿原已完成JSON接续余下样本，没有因观察超时重启正在运行的句柄。部分样本来自原菜单退出后的背景色，C采用各自原入口状态；没有替换C生成的地图像素。
