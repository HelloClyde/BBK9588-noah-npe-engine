# 剧情事件驻留共享与拾取标志别名（2026-10-08）

## 实现

将 `52:74F4..754D` 的 15×6 字节剧情事件表绑定到现有 `story_events` 服务字段，末尾字节单独保留。共享 RAM 逐地址计数为 3266 字节。

| 槽偏移 | 字段 | 装载规则 |
| --- | --- | --- |
| 0..1 | 下一事件 word | 从当前 NPE 文件记录读取 |
| 2..3 | 剧情进度 word | 从当前 NPE 文件记录读取 |
| 4 | 下一模式 byte | 从当前 NPE 文件记录读取 |
| 5 | 保留 byte | 不改写 |

原 source `29:EAA2..EBD2`（runtime `0C:EAA2..EBD2`）仅覆盖当前地图第 11 组提供的槽，其它槽保持。暖读档和重新开始保留全部末尾字节及未提供槽；自身存档仍为 NPESAV22，不增加剧情缓存序列化字段。

模式 14 继续按原 source `4C:4C6E` 取事件号低字节，支持有效的保留槽 15；非法槽的模式 0 和绘图次序沿用已核对的原服务。新增的 RAM 高／低字节、非对齐和跨槽改写直接进入这些既有服务。

## 拾取标志地址规则

原 `37:1460..1490` 先对物件 ID 做 word 减一，再有符号扩展，地址加到 `52:742C`。移除 C 的 256 项独立数组上限：ID 201～290 实际访问相邻剧情表；ID 65535 的结果是偏移 −2，访问物品缓存 `52:742A`。本轮原公共输入验证了部分这些地址的读写。

NPC 条件 9 的 source `40:6BFC..6C20` 对减一后的 word 做零扩展，与拾取有区别；C 按各自原指令计算地址。地址属于已绑定状态时直接读取 World，其它地址只有在当前文件的运行时绑定到该 World 时才读取客机 RAM；不可用地址返回诊断 −2。NPC 条件分发立即传播该错误，避免将负返回值当作条件成立。未宣称原地址异常投递或全部 NPC 条件地址已验证。

原 source `42:30B2..31F2`（runtime `25:30B2..31F2`）的批量地形清除仅扫描前 **100** 个拾取标志，且仅处理值等于 1。C 原先把这一规则扩展到了 256 项，已修正。单次拾取仍按槽直接清除地形，允许本轮验证的高 ID；自身 V19+ 存档保留已经发生的 ID 101～200 地形变化。
