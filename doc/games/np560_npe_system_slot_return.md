# NP560 NPE：系统槽流程、子菜单与返回地图

更新：2026-10-07。生产为纯 C11／SDL2；PRG／WASM 只作离线原厂参考。

## 实际原厂生命周期

`reference_system_slot_return.mjs` 分别从真实标题 boot、新游戏及已有原厂持久槽开始，通过自然 NPC 周期进入系统菜单，执行保存、占用槽读取、空第二槽读取失败。原始 NPE／PRG 未修改。

- 保存成功：13 个非零 NPC 的巡走坐标及朝向保持。
- 读取成功：重新装载当前 NPE 的地图 NPC，8 个巡走槽与读档前不同。
- 空槽读取失败：提示、恢复进入前 LCD、返回地图；NPC 巡走坐标及朝向保持。提示不改变存档内容。

系统返回的主角屏幕坐标为 7／1、视口 36／1、方向 1、逻辑位置 43／2；地图 1、进度 1、钱 100。本轮使用自然巡走后的真实坐标，没有用攻略截图指定 NPC 位置。成功读取的重建由已修复的 `npe_world_restore` 完成；保存及失败路径不清除巡走覆盖。

## 系统子菜单修复

旧 C 将系统子菜单绘制在 `(52,38)`，按 19 像素等距移动反色矩形，进入该层时与原厂相差 3967 个像素。

原 `37:CD3E..CD64` 进入种类 5 并调用 `30:D190`（源 `4D:D190`）；绘制当前 NPE 的 UI base+5 到 `(42,37)`，重叠父菜单右缘。资源仍按当前 NPE 的位图目录定位，没有写入游戏标题或菜单文字。

`4D:D1CA..D266` 和方向服务 `36:4B62..4C78` 给出的反色范围为包含边界的 x=50..105：

| 行 | y 范围 |
| --- | --- |
| 读取进度 | 45..63 |
| 存储进度 | 63..78 |
| 游戏设置 | 78..93 |
| 结束游戏 | 93..110 |

已修正位置、宽度及非等距行范围，并核对四次向下／四次向上的完整循环。

## 返回地图及边缘修复

`37:D094/D0C8/D13A` 设置地图初始化标志，`37:1350..1366` 选择绘图面 1，调用地图初始化绘制。C 原来走普通整图重画，与原厂返回图差 1920 个像素。

进一步反汇编 `03:4214→30:1A54`（源 `4D:1A54..1B68`）发现它按当前背景色清除矩形，不是从旧地图复制边缘。原系统菜单 `49:0080..008A` 将背景色设为 0，地图服务清除上下四行，因此本次三个返回图的这八行全部为 0；进入前地图的八行是 2。不能用旧地图边缘作为这次初始化的恢复来源。

新增 `show_system_map_return` 接入系统保存、成功读取以及提示结束后的读／写失败路径：按已有原地图初始化的主角→NPC 槽→怪物顺序绘制，清除上述边缘，记录当前画面供后续控制器保留。避免外层紧接着重复提交。标题读取及普通菜单取消仍使用各自入口。

本修复只实现已证明的系统入口背景色和地图初始化调用；其它模式的绘图面、颜色状态及完整 LCD 缓存仍待核对，不能从这三条路径宣称全部完成。

## 逐次 C／SDL 验证

`sdl-system-slot-return-probe` 包含真实 `main.c`；使用独立存档路径及未修改 NPE。输入世界的 NPC 覆盖和保留 LCD 取自各原厂入口采样，用于隔离系统槽服务。本轮不证明 C 冷启动 RNG／计时相位与自然巡走过程完全一致。

| 原厂路径 | 提交数 | C／SDL 差异 |
| --- | ---: | --- |
| 保存（含四项上下循环） | 16 | 每次均 0／0 |
| 占用槽读取 | 7 | 每次均 0／0 |
| 空第二槽读取失败 | 10 | 每次均 0／0 |
| 合计 | 33 | 每次均 0／0 |

每个阶段结束检查主角模式／事件／地图／进度／坐标／视口／朝向／金钱及 13 个 NPC 的编号／位置／方向。失败提示和底图的两次提交也逐次比较；原厂逻辑 tick 与 SDL 名义毫秒不视为物理时基等价证明。
