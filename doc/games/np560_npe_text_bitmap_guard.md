# NPE 页面资源调用与异常肖像

日期：2026-10-08。目标是在纯 C／SDL 页面中保留原固件的资源调用及失败后的继续绘制行为。

## 实现

`npe-sdl/text.c` 中的标题、答题、商店、金额、属性、穿戴、库存、仙术列表／目标、道具／装备目标、剧情分页和战后提示，直接把驻留图组基址加序号交给 `npe_render_indexed_resource`。撤去绘图前的宿主位图总数、尺寸和目录元数据检查；保留各页面已有的文字、记录和宿主数组边界检查。

肖像使用 `npe_world_portrait_index`，读取地图人物记录的第八个图号及驻留肖像组基址。原有 `npe_world_portrait_bitmap` 作为元数据查看接口保留，页面绘图不再依赖它。运行时初始化和自身 NPESAV22 格式未改变。

生产程序已绑定 RPG 资源运行时：资源服务执行原来的目录检查、分配、读取、绘图和释放。原服务拒绝图号时，页面继续处理文字、人物数值及输入。适配器无法访问所需内存的错误仍报告失败。没有运行时的元数据查看路径仍有自己的解析限制，本轮不把它算作原调用者异常行为验证。

## 原固件证据

新脚本 `npe-sdl/tests/reference_text_bitmap_guard.mjs` 使用未修改的原 WASM 和游戏容器，恢复已有原地图快照，通过原公共按键进入物品列表和目标页面。诊断修改仅包括人物肖像字、队伍标记、库存、道具缓存和人物数值。

原 PRG 的地图目标肖像调用位于物理 `2F:5A1A`，运行 CODE `12:5A1A`。它调用 `2B:0000` 后清理参数并读取界面状态；没有检查绘图返回值。仙术列表的物理 `3B:6138` 和仙术目标的 `33:F21C` 也直接继续后续绘制。三段调用及其后续指令留存在 `tmp/text-bitmap-guard-source.asm`。

| 原路径 | 肖像字（前三个队员） | 检查点 |
| --- | --- | --- |
| negative-first | 32767／36／38 | 首名队员使用有符号负索引 |
| negative-switch | 36／32767／38 | 切换到负索引队员再切回 |
| bound-first | 200／36／38 | 首名队员图号超出目录 |
| bound-switch | 36／200／38 | 切换到目录外队员再切回 |

当前原肖像组基址为 1667：32767 加基址回绕为 34434，作为有符号 16 位索引为负；200 加基址为 1867，其目录末位置为 14944，超过当前目录的 14240 字节。错误类别由已还原的原资源服务条件判断；新公共输入参考直接证明页面在这些图号下继续提交和响应输入，没有直接捕获原服务返回寄存器。

四条路径各有七次目标／库存页面提交，共 28 帧。逐帧比较完整 240×120 索引画面及实际 SDL 像素，并核对人物属性、肖像、道具缓存、库存、说明分页和输入阶段。两次使用道具后体力由 50 到 64，库存由 4 到 2，随后返回地图。四张最终外层地图画面留存，未计入对照通过。

## 验证

新增 `sdl-text-bitmap-guard-probe` 在实际主程序的物品模态流程中绑定运行时；绑定后把宿主缓存位图总数改为 1，并修改头缓存图组 5～8。28 帧及状态仍完全一致，适配器失败数为 0，说明这些页面使用实际驻留字和原资源服务。

14 项必要短检查退出 0：新异常肖像、属性、穿戴、标题读档、商店、地图道具记录、道具肖像、仙术肖像、装备肖像、战斗道具记录、战后动画、剧情分页、答题及异常音乐菜单。其余页面沿用既有健康参考；没有把健康回归说成所有页面异常组合均已验证。15 个目标最终构建无警告。

冻结证据：`tmp/text-bitmap-guard-report.json`，四例原 JSON／32 张原画面、生成夹具、原反汇编、构建和短检查日志。报告保存源文件、参考画面及日志 SHA-256；五项原 NPE／PRG／WASM／容器哈希保持。
